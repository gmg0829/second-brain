## 分层强化学习 (Hierarchical RL)

### 核心思想

将复杂、长时程任务分解为多个层次，每层负责不同时间尺度和抽象级别的决策。

**对比 flat（单层）RL**：

| 特性 | Flat RL | 分层 RL |
|------|---------|----------|
| **时间尺度** | 单一（每步决策） | 多层（目标 vs 动作） |
| **探索效率** | 低（动作空间大） | 高（目标空间通常更小） |
| **长期信用分配** | 困难 | 自然分解 |
| **计算效率** | 每步都需推理 | 高层推理频率低 |
| **可解释性** | 低 | 高（目标链可追踪） |

### 两层架构示例

```
高层策略 (Manager/Controller)
    ↓ goal g (每 1-10 步输出一次)
低层策略 (Worker/Primitive)
    ↓ action a (每步输出)
环境
    ↓ observation s
    ↑
```

**时间尺度对比**（机器人控制场景）：
- 低层：20 Hz（50ms 一次动作）
- 高层：1 Hz（1 秒一次目标）

### 为什么分层有效？

| 原因 | 解释 | 示例 |
|------|------|------|
| **子任务复用** | 低层技能可组合多个高层任务 | "抓住"、"移动"、"放置"组合成多种任务 |
| **表示压缩** | 目标空间 < 动作空间 | GPS 坐标 vs 关节 torque |
| **层次化探索** | 高层探索目标空间，低层探索动作实现 | 先决定去哪，再决定怎么走 |
| **课程学习** | 高层提供中间监督信号 | 复杂任务分解为简单子任务 |
| **计算效率** | 高层以较低频率推理 | 实时控制中很有价值 |

## 目标表示 (Goal Representation)

### 常见表示方法

| 表示类型 | 形式 | 优点 | 缺点 | 适用场景 |
|----------|------|------|------|----------|
| **语言目标** | "打开门" | 表达能力强、易获取 | 需语言编码器 | 机器人操作、自然语言任务 |
| **视觉目标** | 目标图像 | 直观、无需标注 | 需度量学习 | 物体定位、图像编辑 |
| **状态目标** | $s_g$ (目标状态向量) | 数学上简洁 | 需知道目标状态 | Goal-conditioned RL |
| **隐变量目标** | $z \in \mathbb{R}^d$ | 可压缩、可学习 | 不 interpretable | 端到端学习 |
| **GPS/坐标** | $(x, y, z)$ | 连续、有结构 | 仅限物理任务 | 导航、机械臂 |

### 语言子目标详解

**案例：机器人厨房任务**

```
任务：将苹果放入碗中

高层目标序列：
1. "找到苹果" 
2. "抓住苹果"
3. "找到碗"
4. "将苹果移动到碗上方"
5. "松开手指"

低层目标：每步的关节 torque 控制
```

**语言的优势**：
- 丰富、表达能力强
- 人类可读、可干预
- 可利用预训练语言模型

## 分层强化学习算法

### Option-Critic 框架

**Option**：一个"选项"包含：
- 起始条件（inception）
- 内部策略 $\pi_{option}(a \mid s)$
- 终止条件 $\beta_{option}(s)$

```python
# Option-Critic 伪代码
for episode in range(num_episodes):
    # 选择初始 option
    option = choose_option(s)
    
    while not done:
        # 执行当前 option
        if is_stochastic_option:
            a = sample_from_option_policy(option, s)
        else:
            a = deterministic_option_action(option, s)
        
        s_next = env.step(a)
        
        # 决定是否终止当前 option
        if beta_option(s_next) > threshold:
            option = choose_new_option(s_next)
        
        s = s_next
```

### HIRO (Data-Driven Hierarchical RL)

**高层**：输出目标状态 $g = s_{subgoal}$
**低层**：给定 $g$，最小化 $\|s - g\|$

```python
# HIRO 训练
for iteration in range(num_iters):
    # 1. 收集数据（使用当前策略）
    trajectories = collect_trajectories(pi_high, pi_low)
    
    # 2. 更新低层策略（给定目标）
    for (s, g, a, r) in trajectories:
        pi_low_loss = -log π_low(a|s, g) * A(s, g)
    pi_low = update(pi_low_loss)
    
    # 3. 重新标记高层目标为状态差（off-policy 校正）
    relabeled_goals = relabel_goals(trajectories)
    
    # 4. 更新高层策略
    pi_high_loss = -log π_high(g|s) * A(s, relabeled_goal)
    pi_high = update(pi_high_loss)
```

## 模仿学习中的分层方法

### 分层模仿学习的优势

| 方面 | Flat BC | 分层 BC |
|------|---------|----------|
| **长期任务** | 复合误差累积 | 各层独立学习，更稳定 |
| **中间监督** | 无 | 自然分解子目标 |
| **泛化能力** | 受限于单任务 | 可迁移子技能到新任务 |
| **数据效率** | 需要大量演示 | 子任务数据可复用 |

### DAgger 用于分层策略

**DAgger 流程**：

```python
def dagger():
    # 1. 初始化策略
    pi = initialize_policy()
    
    for iteration in range(num_iters):
        # 2. 用当前策略收集数据
        dataset = []
        for obs in env:
            a = pi(obs)
            dataset.append((obs, a))
        
        # 3. 询问专家在相同状态下的动作
        for obs, a in dataset:
            a_expert = ask_expert(obs)
            dataset.append((obs, a_expert))
        
        # 4. 在聚合数据上训练新策略
        pi = train_bc(dataset)
```

**分层 DAgger**：
- 高层：专家给出语言子目标
- 低层：专家给出实现动作
- 分别训练高低层策略

### 语言子目标案例

**SayCan 风格机器人**：

```
高层策略输入：
├── 当前观察：RGB 图像 + 关节角度
├── 任务描述："place the apple into the red bowl"
└── 视觉语言模型：判断"抓取点"、"放置点"

高层策略输出：
└── 子目标："grasp apple at [x,y,z]"

低层策略输入：
├── 当前观察
├── 子目标 embedding
└── 输出：7-DOF 机械臂关节动作

执行周期：50 Hz
```

## 高层与低层的监督信号

### 低层监督

**Goal-conditioned 奖励**：

$$r^{\text{low}}(s, g) = -\|\phi(s) - \phi(g)\|^2$$

或稀疏版本：

$$r^{\text{low}}(s, g) = \mathbb{1}[\|\phi(s) - \phi(g)\| < \epsilon]$$

### 高层监督

**问题**：高层的"动作"（子目标）如何获得奖励？

| 方法 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **环境奖励** | 子目标达成时给奖励 | 直接 | 需要能判断子目标完成 |
| **稀疏奖励** | 只在高层任务完成时给奖励 | 简单 | 学习困难（sparse RL） |
| **课程学习** | 从简单子目标开始 | 稳定 | 需要手动设计课程 |
| **逆强化学习** | 从演示推断子目标奖励 | 自动 | 计算成本高 |

### 何时重查询高层目标？

| 方法 | 触发条件 | 优点 | 缺点 |
|------|---------|------|------|
| **Goal 达到** | $d(s, g) < \epsilon$ | 最优（完成任务才换） | 完成判断难、可能死循环 |
| **固定超时** | $t - t_{\text{goal}} > T_{\max}$ | 简单、避免死循环 | 不自适应、快慢不一 |
| **失败检测** | 检测到无法完成的信号 | 可恢复 | 需要额外检测器 |

**实践中**：通常用固定超时 + 目标达到检测组合。

## 分层模仿学习的训练流程

### 数据格式

```
演示轨迹：
(obs_0, action_0), (obs_1, action_1), ..., (obs_T, action_T)
    ↓
分段 + 语言标签：
Segment 1: "pick up cup" → actions 0-50
Segment 2: "move to table" → actions 51-120
Segment 3: "place cup" → actions 121-180
```

### 训练目标

**高层策略**：
$$\mathcal{L}^{\text{high}} = -\sum \log \pi_{\theta}^{\text{high}}(g_i \mid s_i^{\text{start}})$$

**低层策略**：
$$\mathcal{L}^{\text{low}} = -\sum \log \pi_{\phi}^{\text{low}}}(a_i \mid s_i, g_i)$$

### 跨任务迁移

**共享低层技能库**：

```
高层策略 → 选择技能
    ↓
技能 1: "pick" → 适用于杯子、苹果、盒子
技能 2: "place" → 适用于多种放置任务
技能 3: "navigate" → 适用于不同目标点
```

## 设计决策总结

| 决策点 | 选项 | 权衡 |
|--------|------|------|
| **目标表示** | 语言/视觉/GPS/隐变量 | 可解释性 vs 通用性 |
| **层数** | 2层/3层/更多 | 表达能力 vs 训练难度 |
| **高层频率** | 高（频繁重规划）vs 低（省计算） | 适应性 vs 效率 |
| **训练方式** | 独立训练/联合训练 | 稳定性 vs 最优性 |
| **是否端到端** | 分层解耦/端到端 | 可解释性 vs 灵活性 |

## 总结

1. **分层 RL 核心**：高层选择目标，低层实现动作，时间尺度解耦
2. **目标表示**：语言（可解释）、视觉（直观）、坐标（结构化）
3. **训练挑战**：各层需适应其他层输出的分布，需要联合调优
4. **探索结构化**：高层探索目标空间，低层探索动作实现
5. **模仿学习结合**：分层BC 可复用子技能，优于 flat BC
