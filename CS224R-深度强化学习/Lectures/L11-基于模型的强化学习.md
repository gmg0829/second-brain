## 课程回顾：强化学习算法全景图

### 在线与离线强化学习分类体系

| 类别 | 定义 | 数据收集 | 代表算法 |
|------|------|----------|----------|
| **在线强化学习 (Online RL)** | 策略直接用于环境交互 | 实时收集，每步更新 | - |
| **离线强化学习 (Offline RL)** | 仅使用固定数据集 | 无需环境交互 | CQL, IQL, AWAC |
| **在线策略强化学习 (On-Policy RL)** | 仅使用当前策略采集的数据 | 每次更新前重新采集 | REINFORCE, Vanilla PG |
| **离线策略强化学习 (Off-Policy RL)** | 可复用历史策略数据 | 通过回放缓冲区 | DQN, SAC, PPO (with IS) |

### 强化学习方法分类详解

```
强化学习算法
├── 策略梯度方法 (Policy Gradient) — 仅学习策略 π
│   └── REINFORCE — 在线策略，使用当前策略数据
│       • 梯度估计：∇_θ J(π_θ) = E_{τ~π_θ}[∇_θ log π_θ(τ) R(τ)]
│       • 优点：理论基础坚实，on-policy 保证收敛
│       • 缺点：数据效率低，每次更新需要重新采集数据
│
├── 演员评论家方法 (Actor-Critic) — 同时学习策略和价值函数
│   ├── PPO (with Importance Sampling) — 在线策略，但利用历史数据
│   │   • 目标函数：L^{CLIP}(θ) = E[min(r_t(θ)·A_t, clip(r_t(θ), 1-ε, 1+ε)·A_t)]
│   │   • 优点：兼顾稳定性和数据效率
│   │   • 缺点：仍受限于 importance sampling 的方差
│   │
│   └── SAC — 离线策略，使用回放缓冲区
│       • 最大熵框架：J(π) = E_{s,a~π}[Q(s,a) - α log π(a|s)]
│       • 优点：自然进行探索，方差低
│       • 缺点：超参数多（温度系数 α）
│
├── Q学习算法 (Q-Learning) — 仅学习Critic，通过贪婪选择隐式定义策略
│   └── DQN — 离线策略，固定目标网络
│       • 目标：min_θ E[(r + γ max_{a'} Q_{θ^-}(s',a') - Q_θ(s,a))²]
│       • 优点：数据效率极高，可复用任意数据
│       • 缺点：off-policy 导致不稳定（需要目标网络、经验回放等技巧）
│
└── 离线约束方法 (Offline Constrained)
    ├── AWR, AWAC, IQL — 约束在数据内（仅考虑数据集中的动作）
    │   • IQL：，通过 expectile 回归学习 value function
    │   • AWAC：优势加权的策略约束
    │   • AWR：优势加权回归
    │
    └── CQL — 通过保守估计隐式约束
        • 额外添加保守项：min_θ E_{s,a~D}[log Σ_a exp(Q(s,a))] - E_{s,a~D}[Q(s,π(a|s))]
        • 优点：理论上保证不会显著差于数据分布
        • 缺点：过度保守可能导致性能下降
```

### 模仿学习 (Imitation Learning)

| 类型 | 特点 | 优缺点 |
|------|------|--------|
| **行为克隆 (Behavioral Cloning)** | 监督学习，直接模仿专家动作 | 简单但无法超越平均表现；分布偏移导致复合误差 |
| **在线模仿学习 (DAgger等)** | 边收集边学习，可查询专家 | 效果更好但需要专家实时参与；成本高 |
| **无需 reward 函数** | 依赖专家数据而非环境 reward | 数据质量要求高；不能利用 reward 信息改进 |

**关键洞察**：从左到右，数据效率逐渐提高，但计算复杂度也增加。

## 基于模型的强化学习 (Model-Based RL) 概述

### 核心思想：学习一个模拟器 (Simulator)

**Model-Based RL 的本质是学习一个预测未来的模型**：

- **状态转移模型 (Dynamics Model)**：学习 $p(s_{t+1} \mid s_t, a_t)$，预测在给定状态下执行动作后的下一个状态
- **奖励模型 (Reward Model)**：学习 $r(s_t, a_t)$，预测获得的奖励
- **视频预测模型**：对图像观测，直接预测未来帧序列

### 应用场景示例

| 领域 | 模型形式 | 示例 |
|------|----------|------|
| 机器人/自动驾驶 | 物理引擎模型 | 预测关节角度、车辆运动轨迹 |
| 自然语言 | 语言模型 | 预测对话回应、故事走向 |
| 游戏 | 规则模拟器 | 国际象棋走子规则（已知） |
| 股票交易 | 市场模拟器 | 预测价格变动（不可直接观察） |

### 为什么需要预测模型？

1. **数据效率**：真实环境交互成本高昂，模拟器可生成大量合成数据
2. **安全性**：避免危险操作（如机器人碰撞）
3. **可解释性**：预测结果可帮助理解系统行为
4. **规划能力**：可以"想象"不同动作序列的后果

### 模型学习的基本流程

```python
# 伪代码：Model-Based RL 基本流程
# Step 1: 收集真实轨迹数据
D_real = collect_trajectories(env, random_or_current_policy)

# Step 2: 学习动态模型
for epoch in range(num_training_epochs):
    for s, a, s_next in D_real:
        loss = ||f_theta(s, a) - s_next||²  # L2 回归
    theta = theta - optimizer(loss)

# Step 3: 使用模型进行规划或数据生成
# 可选A：直接在模型中规划（不需要显式策略）
action_sequence = plan_with_model(f_theta, r_model, s_current, horizon)

# 可选B：生成合成数据训练策略
D_syn = generate_synthetic_data(f_theta, policy, D_real)
policy = train_RL(policy, D_real + D_syn)
```

## 模型学习 (Learning the Model)

### 三种场景对比

| 场景 | 描述 | 处理方式 | 示例 |
|------|------|----------|------|
| **完全已知模型** | 物理规律已知 | 直接使用，无需学习 | 棋类游戏规则、确定性物理系统 |
| **部分已知模型** | 大部分已知，部分参数未知 | 利用先验知识 + 数据拟合未知参数 | 机器人摩擦系数、车辆动力学参数 |
| **完全未知模型** | 无法解析建模 | 从头开始学习神经网络模型 | 流体动力学、人体运动、人类行为 |

### 表征学习：像素级 vs 低维表示

| 方法 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **像素空间预测** | 在原始图像空间预测未来帧 | 可捕捉所有细节、无信息丢失 | 计算成本高、难以忽略无关信息 |
| **低维表示学习** | 先编码到隐空间再预测 $z_t \to z_{t+1}$ | 降低计算复杂度、自动过滤无关信息 | 需要额外的表示学习步骤、可能丢失关键信息 |

```
原始图像 s_t 
    ↓
编码器 Enc(s_t) = z_t  (如 VAE、Contrastive Encoder)
    ↓
动态模型 f(z_t, a_t) = z_{t+1}  (预测隐表示)
    ↓
可选：解码器 Dec(z_{t+1}) ≈ s_{t+1}（重建用于训练）
```

**关键洞察**：低维表示的优势在于丢弃无关信息（如路面纹理的精确颜色），只保留影响决策的关键特征。

**例子**：自动驾驶中，路面纹理变化不影响决策，但其他车辆位置至关重要。

### 奖励模型

Model-Based RL 中通常需要同时学习奖励函数：

- 真实环境交互可能稀疏奖励
- 需要在模拟器中评估动作序列的价值
- 可利用无奖励的过渡数据训练动态模型

## 规划 (Planning) 与模型使用

### 梯度基规划 (Gradient-Based Planning)

**核心思想**：通过反向传播梯度到动作序列来优化奖励。

```python
# 伪代码：梯度基规划
def gradient_based_planning(s_current, model, reward_fn, horizon, num_iters):
    # 初始化动作序列（可学习参数）
    actions = random初始化(horizon)
    actions = torch.Parameter(actions)
    
    for iteration in range(num_iters):
        # 1. 用当前动作序列模拟轨迹
        s = s_current
        total_reward = 0
        for t in range(horizon):
            a = actions[t]
            s_next = model(s, a)  # 预测下一步
            r = reward_fn(s, a)
            total_reward += r
            s = s_next
        
        # 2. 计算总奖励梯度
        total_reward.backward()
        
        # 3. 梯度上升更新动作序列
        with torch.no_grad():
            actions.grad[:] *= -1  # 转为梯度上升
            actions += learning_rate * actions.grad
    
    return actions.detach()  # 返回优化后的动作序列
```

**数学形式**：

$$\max_{a_{t:H}} \sum_{k=t}^{t+H} r(s_k, a_k) \quad \text{s.t.} \quad s_{k+1} = f_\theta(s_k, a_k)$$

其中 $H$ 是规划 horizon，梯度通过链式法则传播：
$$\frac{\partial r}{\partial a_t} = \frac{\partial r}{\partial s_t} \cdot \frac{\partial s_t}{\partial a_t}$$

**适用场景**：
- 模型是确定性的（可直接求导）
- 动作空间连续（可梯度优化）
- 计算资源充足（每次规划需要多次前向传播）

### 采样基规划 (Sampling-Based Planning)

**核心思想**：不依赖梯度，而是在动作空间中采样，评估每个动作序列的价值，选择最优。

#### 随机射击 (Random Shooting)

```python
def random_shooting(s_current, model, reward_fn, num_samples=100):
    best_reward = -float('inf')
    best_actions = None
    
    for _ in range(num_samples):
        # 从先验分布（均匀或高斯）采样动作序列
        actions = sample_from_prior(horizon)
        
        # 模拟并评估
        total_reward = evaluate_trajectory(s_current, actions, model, reward_fn)
        
        if total_reward > best_reward:
            best_reward = total_reward
            best_actions = actions
    
    return best_actions[0]  # 只返回第一个动作（后续会重新规划）
```

#### 交叉熵方法 (Cross-Entropy Method, CEM)

改进的采样方法，通过迭代精化动作分布：

```python
def cem_planning(s_current, model, reward_fn, 
                 num_iterations=10, num_samples=100, num_elites=10):
    # 1. 初始化分布（对角高斯）
    mean = zeros(horizon * action_dim)
    std = ones(horizon * action_dim)
    
    for iteration in range(num_iterations):
        # 2. 采样动作序列
        samples = [sample_gaussian(mean, std) for _ in range(num_samples)]
        
        # 3. 评估并排序
        rewards = [evaluate_trajectory(s_current, actions, model, reward_fn) 
                  for actions in samples]
        elite_indices = argsort(rewards)[-num_elites:]  # 取 top-k
        elites = [samples[i] for i in elite_indices]
        
        # 4. 用精英样本更新分布（最大似然估计高斯）
        mean = mean(elites)
        std = std(elites)  # 可添加正则防止方差过小
    
    return mean[:action_dim]  # 返回第一个动作
```

**对比分析**：

| 特性 | 梯度基规划 | 采样基规划（CEM） |
|------|-----------|------------------|
| **计算效率** | 高（向量化） | 低（需大量采样） |
| **可并行性** | 受限于顺序梯度计算 | 高（可并行采样） |
| **高维动作空间** | 表现好 | 表现差（维度灾难） |
| **不需要梯度** | 需要（否则只能用有限差分） | 不需要 |
| **适用场景** | 神经网络场景、连续动作 | 低维、离散动作、简单模型 |

### 开环 vs 闭环规划

| 类型 | 描述 | 何时使用 | 缺点 |
|------|------|----------|------|
| **开环 (Open-Loop)** | 规划整个动作序列后执行 | 环境稳定、确定性高 | 不适应环境变化、无法恢复错误 |
| **闭环 (Closed-Loop)** | 每步执行后重新规划 | 环境多变、存在干扰 | 计算量大 |

**模型预测控制 (MPC)** 是闭环规划的典型代表：
- 规划短时域 $H$ 的动作序列
- 只执行第一个动作
- 观测新状态后重新规划
- 典型应用：机器人控制（四足行走、机械臂操作）

**Horizon 选择**：
- **短 horizon**：模型预测更准确、计算快，但可能 suboptimal
- **长 horizon**：更接近最优，但误差累积严重、计算成本高

## 使用模型生成合成数据

### 核心思想

使用学到的动态模型生成额外训练数据，弥补真实数据分布的不足。

```
真实轨迹（黑色）→ 在模型中从任意状态开始生成短轨迹（红色）
                ↓
           增加数据覆盖范围，特别是真实交互稀少的状态区域
```

### 合成数据生成算法

```python
def generate_synthetic_data(real_data, model, policy, 
                          horizon=5, num_rollouts=1000):
    D_gen = []
    
    for _ in range(num_rollouts):
        # 从真实数据中随机采样起始状态
        # 这样可以覆盖数据中不密集的区域
        s_start = random.choice(real_data)
        
        # 在模型中执行短 rollout（避免误差累积）
        s = s_start
        for t in range(horizon):
            a = policy(s)  # 使用当前策略选择动作
            s_next = model(s, a)  # 在模型中预测
            r = reward_fn(s, a)  # 需要 reward 模型
            D_gen.append((s, a, r, s_next))
            s = s_next
            if done:
                break
    
    return D_gen
```

### 数据生成策略对比

| 策略 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **从初始状态生成** | $s_0 \sim p(s_0)$ 开始生成 | 简单 | 长 horizon 质量差 |
| **部分轨迹生成** | 从轨迹中间开始生成短片段 | 增加状态覆盖 | 可能不在最优策略分布内 |
| **全覆盖策略** | 从数据中所有状态生成 | 最大覆盖 | 模型误差累积 |

### 与任意 RL 算法结合

生成的合成数据可与任何 RL 算法结合：

| RL 算法类型 | 结合方式 | 注意事项 |
|-------------|----------|----------|
| **On-Policy (如 PPO)** | 只使用当前策略在模型中采样的数据 | 需要频繁重新生成数据 |
| **Off-Policy (如 SAC)** | 存储到回放缓冲区，复用历史数据 | 可混合真实和合成数据 |

## Model-Based RL 的优势与挑战

### 优势详解

| 优势 | 说明 | 示例 |
|------|------|------|
| **数据效率** | 可用模型生成大量合成数据 | 机器人只需少量真实交互 |
| **无奖励数据利用** | 可利用无奖励的过渡数据训练动态模型 | 视频预测任务 |
| **任务迁移** | 模型是任务无关的，可跨任务复用 | 学会物理规律后迁移到新任务 |
| **规划能力** | 可在测试时进行复杂推理 | 象棋、路径规划 |
| **辅助监督信号** | 模型提供额外的预测监督 | 可用于表示学习 |

### 挑战与局限性

| 挑战 | 描述 | 缓解方法 |
|------|------|----------|
| **模型-策略错配** | 优化模型时没有考虑策略利用，导致误差累积 | 定期用真实数据重新训练模型 |
| **分布偏移** | 策略访问的状态可能不在训练数据分布内 | 只生成短轨迹、约束动作空间 |
| **模型误差累积** | 预测误差随 horizon 指数增长 | 使用不确定性估计、退出机制 |
| **超参数敏感** | 模型架构、训练时长、rollout 长度等 | 需要仔细调优 |
| **学习目标错配** | 像素级预测可能包含不相关信息（如天空颜色） | 使用低维表示、多任务学习 |

### 何时使用 Model-Based RL

| 适合的场景 | 不适合的场景 |
|-----------|-------------|
| 物理系统（机器人、车辆）有强结构先验 | 高维图像观测且难以建模 |
| 可获取大量无奖励的过渡数据 | 数据生成成本低于真实交互 |
| 需要快速推理（使用模型预测控制） | 需要极致的渐近性能 |
| 动作空间低维、平滑 | 高度随机、难以预测的环境 |

## 扩展内容：其他类型的模型

除了标准的前向动态模型，还有其他有用的模型：

| 模型类型 | 数学形式 | 应用场景 |
|----------|---------|----------|
| **逆模型** | $p(a \mid s, s')$ | 从状态变化反推动作；动作理解、技能复现 |
| **多步逆模型** | $p(a_{t:t+H} \mid s, s')$ | 从目标状态反推动作序列；目标导向规划 |
| **奖励无关模型** | $p(s_{t+1} \mid s_t)$（无条件） | 发现环境的可供性（affordances） |
| **插值模型** | $p(s_{interp} \mid s_1, s_2)$ | 在两个状态之间插值；路径平滑、运动生成 |

---

## 总结

1. **Model-Based RL 核心**：学习预测未来的模型（动态模型 + 奖励模型）
2. **规划方式**：梯度基（高效、适合高维）和采样基（简单、无需梯度）
3. **数据生成**：从任意状态生成短轨迹，扩大数据覆盖
4. **关键挑战**：模型误差累积、分布偏移、训练稳定性
5. **最佳实践**：短 horizon rollout、周期性用真实数据更新模型、结合不确定性估计
