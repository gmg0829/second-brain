# Stanford CS224R | 大语言模型推理的强化学习 | 第10讲

## 推理作为马尔可夫决策过程

- **将LLM推理建模为MDP**：将文本生成问题形式化为序列决策
  - **状态(State)**：当前提示x + 已生成的推理步骤序列 s = (a_1, a_2, ..., a_t)
  - **动作(Action)**：下一个token或下一个推理步骤（step）
  - **转移(Transition)**：s_{t+1} = s_t ⊕ a_{t+1}（追加新内容）
  - **奖励(Reward)**：r(s, a) = 1 如果最终答案正确，否则0（稀疏奖励）
  - **目标**：学习策略π(a_t | s_t)，最大化期望累计奖励

- **稀疏奖励问题**：最终结果才能反馈，过程无监督信号
  - 数学表达：r(s, a) = 0 对所有中间步骤，直到episode结束才 r=1 或 r=0
  - 问题：梯度信号无法反向传播到中间决策（只有最终有监督）
  - 类比：告诉学生"考试得了100分"但不告诉具体哪些题做对了
  - 解决方向：过程奖励模型(PRM)、蒙特卡洛树搜索(MCTS)、自我验证

- **为什么推理任务特殊**：与标准RL的区别
  - **动作空间**：离散token空间（词汇表V通常5万~10万）
  - **episode长度**：可能数百到数千个token（比标准RL长得多）
  - **状态空间**：组合爆炸（任意长度推理序列）
  - **奖励延迟**：数千步后才获得单一信号
  - **验证可检验**：数学/代码任务的正确性可自动判定（无需人类）

## SFT的局限性

- **SFT的核心问题**：三大局限制约推理能力提升
  - **需要高质量人工解答**：SFT效果依赖人类书写的正确推理过程
  - **数据稀缺**：高质量推理数据有限，预计2028年左右耗尽
  - **虚假步骤问题**：某些错误步骤偶然导致正确结论，SFT无法区分
  - SFT本质是模仿，无法自主发现超越人类的新推理路径

- **数据稀缺的具体挑战**：
  - **数学奥赛数据**：高质量竞赛解答数量有限（约10万条）
  - **代码生成数据**：正确且优雅的解题方案更稀缺
  - **科学推理数据**：需要专业领域知识，难以大规模获取
  - **估算**：现有高质量数学推理数据约1000万样本，2028年可能耗尽
  - **解决方向**：自我生成数据、RL发现新解法、合成数据

- **虚假步骤(Spurious Steps)**：错误推理却碰巧得到正确答案
  - 例子：数学证明中用了一个错误的等式变换，但最后答案碰巧对了
  - 后果：SFT会学习这个虚假步骤，因为它导致了正确答案
  - 危害：模型在类似问题上会重复虚假推理，因为只学到了"正确答案=好"
  - 深层原因：模仿学习不区分因果关系与相关性
  - **因果混淆(Causal Confusion)**：SFT学到的是相关性而非因果推理

- **拒绝微调(Rejection Fine-Tuning, RFT)**：自我生成+过滤
  - 核心思想：不要模仿，要筛选——自己生成正确答案，只学对的
  - 流程：
    1. 给定问题x，采样N个候选解答{y_1, ..., y_N}
    2. 验证每个解答的正确性（自动评测或人类标注）
    3. 只保留正确答案 {(x, y_i) | y_i is correct}
    4. 在过滤后的数据上做SFT
  - 效果：RFT比SFT数据效率高2倍（达到同样正确率需更少数据）

- **RFT的问题与局限**：
  - **过拟合风险**：模型反复生成自己已会的解法，强化固有模式
  - **多样性丧失**：拒绝错误的同时间距了潜在的正确路径
  - **验证依赖**：需要可靠的正确性判断（数学/代码有，开放问答未必）
  - **效率问题**：采样-验证-训练循环，计算成本高

## 过程奖励模型(PRM)

- **PRM核心思想**：对每个推理步骤打分，而非仅评估最终结果
  - 与结果奖励模型(ORM)对比：ORM只给最终答案打分，PRM给每步打
  - 奖励结构：r(s_1), r(s_2), ..., r(s_n) 对每个步骤给出0~1的评分
  - 优势：更细粒度的学习信号，能识别哪一步出了问题
  - 应用：引导蒙特卡洛树搜索、策略学习时提供过程监督

- **PRM的训练方式**：
  - **数据标注**：需要人工标注每步是否正确（比仅标注结果贵10-100倍）
  - **过程监督信号**：告诉模型具体哪个步骤是对的/错的
  - **自动PRM**：用结果监督作为伪标签（如果最终答案对则所有中间步骤大概率对）
  - **小模型PRM**：用小模型标注大模型生成步骤（规模 Trade-off）

- **Q函数视角下的推理**：评估每个推理前缀的价值
  - Q(s) = E[最终成功 | 从前缀s开始推理]
  - 含义：给定当前推理步骤序列s，模型最终答对的概率是多少
  - 估计方法：从状态s采样大量完整推理路径，看成功比例
  - 用途：识别推理卡点（Q(s)低的步骤需要改进）

- **步骤级优势计算**：
  - A(s_t) = Q(s_t) - V(s_{t-1})（当前步骤相对于前一步的优势）
  - 或简化：A(s_t) = r(s_t) - baseline（单步优势）
  - baseline通常用均值：r(s_t) - μ_组内
  - 正优势：此步骤比平均步骤更好；负优势：更差

## GRPO：群体相对策略优化

- **GRPO核心思想**：组内相对比较替代绝对奖励，省去Critic网络
  - 背景：PPO需要value network(Critic)来估计V(s)，增加计算成本
  - GRPO创新：对于同一问题采样G个响应，计算组内相对优势
  - 无需Critic：相对排名本身就是优势信号
  - 数学表达：A_i = (r_i - μ_组) / σ_组（标准化后的组内优势）

- **GRPO vs PPO对比**：
  - **PPO**：需要独立Critic网络估计V(s)，双网络结构
  - **GRPO**：用组内均值作为baseline，无需Critic
  - **计算节省**：省去50%的网络参数和前向传播计算
  - **优势来源**：组内比较天然控制了问题难度差异
  - **效果**：在数学推理任务上GRPO与PPO效果相当

- **GRPO的组内相对优势计算**：
  - 对同一问题x，采样响应{y_1, ..., y_G}
  - 每条响应得到最终奖励{r_1, ..., r_G}
  - 组均值：μ = (1/G) Σ r_i
  - 组标准差：σ = sqrt((1/G) Σ (r_i - μ)^2)
  - 标准化优势：A_i = (r_i - μ) / σ（避免尺度问题）
  - 无正确答案时：用相对排名r_i代替二进制正确性

- **GRPO在数学推理中的应用**：
  - 采样：每个数学问题采样8~16个解答
  - 正确性判断：验证最终答案是否匹配标准答案
  - 优势计算：正确答案的响应获得正优势，错误答案获得负优势
  - 更新：策略倾向于生成类似正确答案的响应
  - 效果：DeepSeek-Math在 MATH 基准上从30%提升到50%+

## 推理时扩展与测试时计算

- **测试时计算(Test-Time Computation)**：推理阶段分配更多计算资源
  - 背景：训练后模型能力固定，推理时可动态分配计算
  - 方法：让模型在推理时"思考更久"（更多token）
  - 技术：Chain-of-Thought(CoT)、Self-Consistency、Tree of Thoughts
  - 效果：推理时计算比训练时计算更灵活（按需分配）

- **CoT(Chain-of-Thought)推理**：显式生成中间推理步骤
  - 核心：让模型输出推理过程，而非直接给答案
  - 效果：在数学、逻辑任务上显著提升（GSM8K上30%→70%+）
  - 机制：语言模型通过生成解释"访问"更多计算
  - 变体：Zero-shot CoT、Few-shot CoT、Self-Verification

- **过程奖励引导的搜索**：
  - **Best-of-N采样**：采样N个解答，选择PRM评分最高的
  - **束搜索(Beam Search)**：维护多个高概率推理路径
  - **蒙特卡洛树搜索(MCTS)**：平衡探索与利用
  - **PRM引导**：在分叉点用PRM选择下一步，而非贪婪
  - 效果：PRM引导搜索在复杂推理上优于贪婪解码

- **DeepSeek R1 / OpenAI o1风格模型**：
  - **OpenAI o1**：在推理时使用隐式CoT，通过RL学会隐式推理策略
  - **DeepSeek R1**：开源版本，展示推理时思考（thinking）过程
  - **关键洞察**：RL不仅提升训练数据质量，还教会模型"何时思考更长"
  - **涌现能力**：o1/R1在推理任务上出现质的飞跃（竞赛数学、代码）
  - **Scaling Law新视角**：测试时计算与训练时计算可互补

## 代码强化学习案例

- **AlphaCode**：DeepMind竞赛编程AI
  - 任务：解决编程竞赛问题（需要算法设计的复杂问题）
  - 数据：Codeforces上12万+问题，数十万测试用例
  - 奖励定义：编译成功 + 测试用例通过数
  - 训练方法：海量数据上做SFT + PPO微调
  - 生成策略：每个问题采样百万量级代码，用测试用例过滤
  - 结果：在500万选手中排名前54%（竞赛级水平）

- **代码RL的特殊优势**：
  - **可自动验证**：编译+测试用例自动判断正确性
  - **无人类标注成本**：正确/错误由机器判定
  - **细粒度反馈**：每个测试用例失败给出具体错误信息
  - **多样性激励**：生成多样化正确解法，而非仅模仿标准答案

- **RL vs SFT在代码任务上的对比**：
  - **SFT**：需要人工编写的高质量代码解答
  - **RL**：可以探索多种正确解法，甚至发现比标准答案更好的
  - **RL优势**：在学习新算法/数据结构时更强（不依赖已有解答）
  - **挑战**：大动作空间（任意代码）+ 长序列 + 稀疏奖励

## 主动学习与偏好数据

- **主动学习(Active Learning)**：智能选择最有价值的查询
  - 核心思想：模型不知道自己不知道什么——需要主动发现知识盲点
  - 策略：选择模型最不确定的问题/步骤来请求标注
  - 不确定性估计：PRM预测的方差、Q值的置信度、softmax熵
  - 效果：用更少数据达到同样精度（标注效率提升2-10倍）

- **推理中的主动学习应用**：
  - **发现问题边界**：找出模型开始出错的推理步骤
  - **优先标注**：只标注模型不确定的步骤，减少标注成本
  - **迭代精炼**：学一点→识别弱点→优先学弱点→循环提升
  - 在数学/代码推理中特别有效（正确性可自动判定）

- **偏好数据的高效利用**：
  - **自我生成+过滤**：模型生成候选，人工/自动筛选
  - **相对比较**：非绝对评分，只比较哪个更好
  - **分层抽样**：覆盖不同难度、类型的问题
  - **难度匹配**：选择略高于模型当前能力的题目（最优学习区）

## 推理RL的关键洞察

- **为什么推理任务需要RL而其他LLM任务不用**：
  - 标准LLM任务（对话、写作）：奖励可由reward model近似，信号丰富
  - 推理任务：最终正确性是唯一可靠信号，中间步骤无法自动评估
  - RL提供端到端优化框架，直接最大化最终正确率

- **RL教会模型什么**：
  - **何时使用特定策略**：如"这类几何问题用坐标法更好"
  - **何时回溯**：发现错误时修正而非一条路走到黑
  - **何时深入思考**：对难题分配更多推理token
  - **元认知能力**：学习"知道自己不知道什么"

- **RL for Reasoning的未来方向**：
  - **更细粒度奖励**：从二元正确/错误到多维度评分
  - **自我验证集成**：让模型在推理中验证中间步骤
  - **更长上下文推理**：处理需要数百步的复杂证明
  - **多模态推理**：代码执行、数学符号、视觉图表联合推理

## 算法对比总结

| 方法 | 奖励类型 | Critic | 适用场景 | 局限性 |
|------|----------|--------|----------|--------|
| **SFT** | 结果标签 | 无 | 数据充足 | 无法超越人类 |
| **RFT** | 正确性过滤 | 无 | 可自动验证 | 过拟合风险 |
| **PPO** | 结果/过程 | 需要 | 复杂推理 | 计算重 |
| **GRPO** | 组内相对 | 无需 | 数学推理 | 需多采样 |
| **DPO** | 偏好对 | 无需 | 偏好数据 | 间接优化 |
