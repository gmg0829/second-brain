## 自主学习与机器人强化学习概述

### 为什么机器人无法实现完全自主？

传统强化学习算法在物理机器人上运行时，并非完全自主。核心问题在于**重置（Reset）需求**：

- RL假设智能体从初始状态分布出发，经过多次试验（episode）学习
- 每次试验结束后，需要将机器人或场景重置到初始状态
- 实际物理世界中，重置通常依赖人工干预（human intervention）

```
典型RL训练循环：
初始化策略 π → 采集轨迹数据 → 更新策略 → 重置环境 → 重复
```

**问题场景示例：**

| 任务类型 | 错误后果 | 重置需求 |
|---------|---------|---------|
| 篮球场导航 | 走错路后远离目标 | 需导航回起点或目标 |
| 抓取马克杯 | 碰倒马克杯 | 需将马克杯放回机器人可及范围 |
| 书本上书架 | 失误导致书本位置改变 | 需重新摆放书本 |

人类专家在机器人学习中承担大量重置工作（如视频中演示者不断复位机器人）。

### 自主强化学习的核心目标

**定义：Single Life Reinforcement Learning（单次生命强化学习）**

- 初始化场景一次
- 智能体自主与环境交互，无环境重置
- 偶尔重置（如每10万步）用于故障恢复

### 两种评估指标

| 评估方式 | 含义 | 适用场景 |
|---------|------|---------|
| **部署策略评估（Deployed Policy Evaluation）** | 学到的策略从初始状态分布出发能获得多少奖励 | 一次性任务（如Mars rover收集数据后不继续工作） |
| **生命周期奖励（Lifetime Reward）** | 学习过程中平均每步获得的奖励 | 持续运行系统（如工厂机器人持续工作） |

**数学定义：**

```python
# 部署策略评估（类似标准RL目标）
J_deployed = E_{s0 ~ p(s0), π}[∑_{t=0}^h γ^t r(s_t, a_t)]

# 生命周期奖励
J_lifetime = lim_{h→∞} (1/h) E[∑_{t=1}^h r_t]
```

两种指标在长horizon设置下可能冲突——策略可能"放弃"达到目标，而是在途中获取容易的奖励。

## 延长Episode长度的朴素方法与局限性

### 朴素方法：增加Episode长度

直觉：如果减少重置频率 → 提高自主性 → 只需用标准SAC/PPO训练

### 实验结果（Fish Locomotion Task）

| Episode长度 | Reset频率 | 最终策略性能 |
|------------|----------|------------|
| 1,000步 | 频繁 | 接近最优 ✓ |
| 2,000步（2x） | 减少50% | 明显下降 |
| 10,000步（10x） | 非常低 | 几乎无法学习 |

**观察：即使简单任务，增加episode长度也会导致学习失败。**

### 失败原因分析

**原因1：状态偏移（Drift）**
- 智能体可能犯错进入难以恢复的状态空间区域
- 没有重置，永远无法回到"正确轨道"

**原因2：状态分布坍缩（Distribution Collapse）**
- 一旦到达目标状态，策略可能持续停留在该区域
- 采集的数据集中在目标附近，忽略起始区域
- 最终策略无法从初始状态正确执行任务

```
最优状态分布（玫红色）：
  ○初始状态 → 路径 → ●目标状态

实际情况（自主学习）：
  ○初始状态 → ？ → [聚集在目标附近的数据]
```

**根本问题：Episode之间缺乏有效连接**

## Forward-Backward RL：学习逆向重置策略

### 核心思想

**不依赖外部重置，而是学习一个逆向策略（Backward Policy）将智能体带回初始状态。**

```
Forward Policy π_f: 执行任务（初始状态 → 目标）
Backward Policy π_b: 撤销任务（目标 → 初始状态）

训练流程：
1. 初始化，采样初始状态 s0
2. 执行 π_f h 步，积累forward数据
3. 更新 π_f（最大化 forward reward R_f）
4. 执行 π_b h 步，积累backward数据
5. 更新 π_b（最大化 backward reward R_b = 到达初始状态分布的奖励）
6. 重复，循环往复
```

### 关键设计细节

- **R_f（Forward Reward）**：标准任务奖励（如到达目标位置）
- **R_b（Backward Reward）**：到达初始状态分布的奖励（可用状态判别器实现）
- **无需在backward后重置**：直接进入下一个forward阶段

### 优势与局限

| 优势 | 局限 |
|-----|-----|
| 概念简单，易实现 | backward策略本身对完成任务无直接贡献 |
| 可与任意on-policy算法结合 | 需要额外reward函数 |
| 完全自主的学习循环 | 某些任务backward可能比forward更难 |

### 数据复用技巧

- 两个策略可共享replay buffer
- 可共享视觉编码器等参数
- 但两者任务本质不同，参数共享需谨慎

## 基于演示的METAL算法：Reset-Free RL的改进

### 核心改进

**不回到"初始状态分布"，而是回到"专家演示状态分布"。**

### 方法流程

**额外输入：少量专家演示轨迹**

1. 从初始状态采样，运行forward policy
2. 运行backward policy，但reward为"接近专家演示状态"
3. 判别器训练：区分policy访问状态 vs 专家演示状态
4. backward policy学会将智能体推向专家轨迹覆盖的状态空间

### 关键创新：Reward学习

```python
# 判别器 D(s) 训练目标
#   D(s) = 1: 来自专家演示
#   D(s) = 0: 来自当前policy

# Backward Reward
R_b(s) = -log(1 - D(s))  # 欺骗判别器认为policy状态是"专家的"
```

### 相比Forward-Backward RL的优点

- 状态覆盖更广：专家演示可能包含多条成功轨迹
- 学习效率更高：reset回到更多样化的中间状态
- 避免坍缩：不会只停留在goal状态

### 理论解释

若backward policy只重置到goal state，判别器会识别出这与专家演示不符（goal state在专家演示中概率低）。因此策略必须重置到多样化的中间状态。

## 基准测试：Earl Benchmark

### 实验设置

| 参数 | 值 |
|-----|---|
| Reset频率 | 每200,000步才重置一次 |
| 评估指标 | 最终策略从初始状态分布出发的成功率 |
| 环境 | 多种机器人操控任务 |

### 对比算法

| 算法 | 描述 |
|-----|------|
| SAC (无reset-free) | 标准off-policy算法，少量reset |
| Oracle | 每episode后立即reset（理论上限） |
| RMA+ | 基于探索的reset-free方法 |
| Forward-Backward RL | 本文方法 |
| METAL | 基于演示的方法 |

### 结论

- 无特殊设计的算法在低reset频率下几乎无法学习
- Forward-Backward和METAL在简单任务上表现相近
- 复杂任务中，METAL等基于演示的方法显著优于纯探索方法

## 多任务循环学习：Autonomous RL的扩展框架

### 动机

**现实任务往往包含多个子任务，且子任务之间存在天然的循环关系。**

### 例子：制作咖啡

```
任务流程：
1. 将杯子放入咖啡机
2. 拿起杯子（若掉落）← 这里失败后练习
3. 打开咖啡机
4. 倒咖啡
5. 将杯子放回桌面
```

### 循环图结构

```
State-A → Task-1 → State-B → Task-2 → State-C → Task-3 → ...
     ↑                                            ↓
     └────────────── 通过backward/恢复策略 ───────────┘
```

### 算法框架

1. **Task Proposer（任务提议器）**：基于当前状态提议可执行的子任务
2. **Multi-task Policy π(z|a, s)**：给定任务描述z，执行对应任务
3. **持续循环**，无外部重置

### 任务提议方法

| 方法 | 描述 | 优缺点 |
|-----|------|-----|
| 预定义图 | 人工设计任务转换图 | 简单可靠，但需人工定义 |
| 语言模型提议 | VLM根据当前状态生成可行任务 | 更通用，但需LLM调用 |

**LLM提议示例：**
- 当前状态：机器人面对微波炉
- 提议："打开微波炉" / "拿起香蕉" / "推动茄子"  （可执行）
- 不可提议："拿起胡萝卜" （场景中无胡萝卜）

### 与层级强化学习的区别

| 方面 | 层级RL | 多任务循环 |
|-----|--------|-----------|
| 上层策略目标 | 选择能达成最终目标的子任务 | 提议当前可执行的多样化任务 |
| 关注点 | 目标导向（goal-directed） | 探索导向（exploration-oriented） |
| 任务覆盖 | 单一目标相关 | 广泛覆盖多种行为 |

## 本讲小结与要点

### 核心问题
- 物理机器人上的RL需要频繁重置，阻碍完全自主学习
- 需要设计能在无重置条件下学习的算法

### 关键算法

| 算法 | 核心思想 | 适用场景 |
|-----|---------|---------|
| Forward-Backward RL | 学习逆向策略undo任务 | 任务可逆、backward较简单 |
| METAL | 基于专家演示学习重置状态分布 | 有少量演示数据 |
| 多任务循环 | 根据状态动态选择任务形成循环 | 多子任务、任务间有依赖关系 |

### 实践注意事项

- **环境建模**：仿真环境可通过`env.reset()`完全重置，但物理世界不能
- **奖励函数**：自主学习需设计额外的"重置奖励"或利用判别器学习
- **任务设计**：设计可逆的任务可简化自主学习难度
- **与Sim2Real结合**：仿真中训练 + 物理世界部署是当前主流范式
