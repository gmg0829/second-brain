# Stanford CS224R | 元强化学习 | 第 13 讲

## 核心思想

- **元强化学习（Meta-RL）**：从大量任务中学习"如何学习"，使智能体能快速适应新任务
- **关键洞察**：不是学习一个固定策略，而是学习一个可以快速微调的策略初始化或表示
- **两重优化**：内层（快速适应新任务） + 外层（跨任务泛化）

## 问题形式化

- **任务分布** $p(\mathcal{T})$：每个任务 $\mathcal{T}_i$ 有自己的奖励函数和动力学
- **Meta-training**：从任务分布中采样训练，学习适应能力
- **Meta-test**：遇到全新任务，只用少量交互就能适应

```
标准 RL:
max_π E[R^τ]          （单个任务）

Meta-RL:
max_π E_{τ∼p(τ)} [E_{θ∼adapt(π,τ)} [R^θ]]
                    ↑      ↑       ↑
                  策略   快速适应   新任务的回报
```

## Black-Box 元RL 方法

- **思路**：用 RNN 维护内部状态，直接将历史经验编码到隐藏状态中
- **代表算法**：RL²、Meta-RL（Schaul 等）
- **架构**：RNN 读取 $(s_t, a_t, r_t)$ 序列，输出策略，隐藏状态自动编码任务信息

```
Black-Box 元RL：
(s_t, a_t, r_t, hidden_t) → RNN → (a_{t+1}, hidden_{t+1})
```

- **优点**：灵活，任何序列模型都可以用
- **缺点**：需要大量 meta-training 任务，表达能力受限于 RNN 容量

## 序列模型架构

| 架构 | 优点 | 缺点 |
|------|------|------|
| Vanilla RNN | 简单，online learning | 梯度难训练 |
| LSTM/GRU | 长程依赖，梯度稳定 | 仍有限制 |
| Transformer | 并行训练，长程建模强 | 推理成本高 |

- **Transformer 作为元RL 序列模型**：将 meta-learning 框架为 sequence modeling 问题
  - 输入：整个 task 交互历史
  - 输出：下一个动作或 value 估计

## 探索-利用权衡（Meta-RL 视角）

- **Meta-test 时的新任务探索**：agent 必须快速识别任务本质
- **Posterior sampling for meta-RL**：为每个任务维护一个后验分布 $p(\text{task} | \text{history})$，然后从后验采样
- **Posterior sampling 优点**：自动平衡探索和利用（自然处理 exploration-exploitation）

## 变分信息瓶颈

- **目标**：学到一个紧凑的任务表示 $z$，只保留对适应有用信息
- **变分下界**：
```
max_π E_{z∼q(z|τ)} [R(τ)] - β · KL(q(z|τ) || r(z))
                         ↑                    ↑
                      任务回报            限制表示复杂度
```
- **好处**：防止过拟合到 meta-training 任务，提升泛化

## 部分可观测 MDP（POMDP）视角

- **元RL = 在 POMDP 中学习**：任务身份是隐藏状态，历史经验是观测
- **信念状态（belief state）**：对任务身份的 belief，通过贝叶斯更新维护
- **DREAM 算法**：用变分推断近似后验，用 dream 机制增强经验

## 测试时计算（Test-Time Compute）

- **大语言模型 analogy**：类似 LLM 在推理时用更多计算（chain-of-thought）提升性能
- **Meta-RL 测试时策略更新**：在遇到新任务时，做更多 gradient steps 或更多探索
- **Test-time 学习 vs 固定策略**：测试时继续学习 vs 只是用预训练策略

## 关键设计决策

| 问题 | 选项 | 权衡 |
|------|------|------|
| 适应方式 | 黑箱 vs 梯度 | 灵活性 vs 效率 |
| 任务表示 | 显式 vs 隐式 | 可解释 vs 表达力 |
| 探索机制 | 内在激励 vs posterior sampling | 通用 vs 最优 |
| 测试时更新 | 无 vs 在线微调 | 速度 vs 适应质量 |
