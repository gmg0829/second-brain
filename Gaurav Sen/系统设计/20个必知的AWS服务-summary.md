## 核心观点

### 20. AWS Neptune — 图数据库

- **本质**：AWS 托管的 Neo4j 版本
- **优势**：开源数据库 Neo4j 拥有清晰的 API、完善的文档，AWS 在此基础上提供部署、扩缩容、监控、告警、硬件故障处理、软件升级等全套托管能力
- **适用场景**：社交网络、基于位置的应用程序（LBS）
- **注意**：除非有图数据库需求，否则不太可能用到，只需知道 AWS 有这个解决方案即可

### 19. AWS Cognito — 身份认证

- **本质**：AWS 的身份认证（Authentication）机制
- **解决的问题**：验证"这个用户是否是他们声称的那个人"
- **对比**：有 SSO、OAuth、JWT 等多种方案，但作为工程师不应自己造轮子
- **优势**：Cognito 完全托管，保证正确的安全机制和扩缩容，节省开发成本

### 18. AWS TimeStream — 时序数据库

- **本质**：AWS 提供的时序（Time Series）数据库
- **底层**：可能是 InfluxDB、OpenTSDB 或 AWS 自研，不重要
- **适用场景**：需要按时间维度聚合指标、快速获取最近指标的场景
- **优势**：自动扩缩容、软件自动升级，封装了时序数据处理的复杂性

### 17. AWS OpenSearch — 搜索引擎

- **本质**：基于 ElasticSearch 的文本搜索解决方案
- **底层**：ElasticSearch 拥有强大的子字符串搜索算法
- **适用场景**：构建任何类型的搜索引擎、搜索文档和讨论内容
- **注意**：价格较贵，只有"搜索优先"（search-first）的应用才值得使用；否则关系型数据库的简单查询也能满足需求

### 16. AWS Lambda — 无服务器计算

- **本质**：AWS 的无服务器（Serverless）计算服务
- **工作原理**：请求到达 AWS → AWS 启动可运行代码的实例 → 处理请求并返回响应，整个过程自动完成
- **优势**：
  - **自动扩缩容**：请求增加时自动扩展
  - **无需管理服务器**
- **缺点**：相比预留的 EC2 实例，Lambda 成本更高
- **适用场景**：初创公司或业务规模不确定时，Lambda 可以解决扩缩容的不确定性问题，让你专注于业务问题

### 15. AWS Kinesis Streams — 流数据

- **本质**：事件流（Event Streaming）服务
- **工作原理**：将用户行为抽象为事件（event），发送到流中；事件最终写入 S3 等存储，再基于此运行数据分析
- **典型查询示例**："过去7天有多少印度用户点击了这个按钮？"
- **优势**：这类分析查询成本高，不应打在主数据库上；Kinesis 将事件流与主数据存储分离
- **与 Kafka 对比**：Kafka 功能更丰富但也更复杂；初创公司可能不需要 Kafka 的全部特性，SQS 是更简单的替代方案

### 14. AWS Glacier — 冷存储

- **本质**：低成本、极少访问的冷数据存储方案
- **适用场景**：
  1. **合规存储**：如金融交易记录，允许 12-24 小时延迟响应警方调取需求
  2. **备份原始素材**：如 8K 直播视频原始素材，实际只提供低分辨率版本给用户，原始素材存入 Glacier 备份
- **特点**：存储成本极低，只要保证数据耐久性即可

### 13. AWS SQS — 简单队列服务

- **本质**：消息队列（Message Queue）服务
- **支持模式**：Publisher-Subscriber（发布-订阅）和事件驱动架构
- **优势**：成本低、扩缩性好
- **与 Kafka 对比**：Kafka 功能更丰富但复杂度也更高；初创公司不需要 Kafka 的全部特性时，SQS 是很好的替代方案

### 12. AWS DMS — 数据迁移服务

- **本质**：Database Migration Service（数据库迁移服务）
- **重要性**：在组织生命周期中，数据迁移是不可避免的操作
- **风险**：手动迁移容易出错（可能导致客户无法访问网站），更可怕的是**数据丢失或系统处于不一致状态**
- **适用场景**：中大型组织；初创公司可能因为规模限制无法使用（DMS 面向大型 Aurora 实例）

### 11. AWS DynamoDB — NoSQL 数据库

- **本质**：AWS 的 NoSQL 键值数据库，可大规模扩缩
- **核心机制**：
  - **分区键（Partition Key）**：决定数据如何分片
  - **排序键（Sort Key）**：在分片内对记录排序
- **与 Cassandra 的关系**：Cassandra 受 DynamoDB 启发很大
- **注意事项**：DynamoDB 成本较高；AWS 建议初创公司和中型公司优先考虑 SQL 数据库而非 NoSQL
- **适用场景**：大型组织确实需要 NoSQL 的场景

### 10. AWS ElastiCache — 缓存

- **本质**：完全托管的内存缓存服务
- **兼容**：Redis 和 Memcached（全球最流行的两种缓存实现）
- **优势**：快速、可扩缩、全托管
- **适用场景**：需要全局缓存时，直接使用 ElastiCache 而不是自己部署
- **注意**：如果需要极高的自定义控制（如自定义置换算法），可能需要自己实现；InterviewReady 就在使用自建缓存

### 9. AWS SES — 简单邮件服务

- **本质**：Simple Email Service，用于发送电子邮件
- **姐妹服务**：Simple Notification Service（SNS，用于发送短信）
- **适用场景**：营销邮件、OTP 验证码等事务性邮件
- **优势**：成本低（可能是最便宜的邮件解决方案）、完全托管、支持大规模发送（5万封邮件同时发送也能快速扩展）
- **SES 与 SNS**：SES 发邮件，SNS 发短信/推送通知

### 8. AWS ELB — 弹性负载均衡器

- **本质**：Elastic Load Balancer，AWS 的负载均衡解决方案
- **核心功能**：接收传入请求，决定将请求路由到哪台服务器
- **优势**：经过大量生产环境测试、易于设置、自动扩缩
- **建议**：请不要自己造负载均衡器；如果已经在用 Nginx 等方案，继续用就好

### 7. AWS CloudWatch — 监控与日志

- **本质**：AWS 的完整监控和日志解决方案
- **功能**：
  1. **自动监控**：EC2 实例的内存消耗、IO 操作等自动追踪记录
  2. **告警**：服务器宕机等情况下自动通知（如 Slack）
  3. **日志聚合**：多服务器场景下，集中式日志查看，无需 SSH 到每台机器
- **优势**：无需自己搭建监控系统

### 6. AWS API Gateway — API 网关

- **本质**：统一的 API 暴露、管理、版本控制和扩缩平台
- **核心价值**：将所有应用的 API 集中在一处管理，自动处理版本控制和扩缩
- **是高频使用的核心服务之一**

### 5. AWS Route 53 — DNS 服务

- **本质**：AWS 的 DNS（域名系统）解决方案
- **核心场景**：购买域名（如 xyz.com）后，需要将域名映射到公网 IP 地址；Route 53 管理这个映射关系
- **优势**：当后台基础设施变化时，自动更新 DNS 映射，用户无感知；完全托管

### 4. AWS CloudFront — CDN

- **本质**：AWS 的地理分布式缓存网络
- **典型场景**：印度和美国用户观看不同偏好的电影内容；将对应地区的内容缓存到最近节点
- **工作原理**：配合 S3 使用，将 S3 存储桶（bucket）中的内容通过 CDN 分发到全球
- **优势**：设置极其简单（相比 Akamai 这类第三方方案），与 AWS 生态无缝集成

### 3. AWS RDS — 关系数据库服务

- **本质**：托管的 SQL 数据库服务
- **兼容**：PostgreSQL、MySQL
- **存储选项**：
  - Elastic Block Storage（普通块存储）
  - **Aurora**：更高可用性、更高持久性的数据库架构，6个数据副本分布式保存；成本更高但数据安全更有保障
- **使用建议**：InterviewReady 正在使用 Aurora，从未出现数据持久化或可用性问题

### 2. AWS S3 — 简单存储服务

- **本质**：对象存储服务（可理解为"文件存储"）
- **特点**：
  - 极其便宜（比 Glacier 贵但仍然非常便宜）
  - 几乎无限的可扩展性
  - 极高的耐久性
- **适用场景**：视频存储、日志持久化、分析记录等
- **常见用途**：存储分析数据、日志、视频等各类数据

### 1. AWS EC2 — 弹性计算云

- **本质**：AWS 的核心——虚拟服务器，是整个架构的基石
- **你需要提供的东西**：操作系统、代码运行环境
- **EC2 变种**：
  - **通用型（General Purpose）**：适合初创公司，不需要精确判断业务类型时首选
  - **内存优化型（Memory Optimized）**：大量缓存数据场景
  - **计算优化型（Compute Optimized）**：大量计算型任务（如视频转码）
- **Lambda vs EC2**：
  - Lambda 免运维、自动扩缩，但成本更高
  - EC2 有预留实例（Reserved Instances）折扣，成本更低
  - 两者扩缩容能力相当，但 Lambda 不容易过度预配置

## 工程视角总结

> "Don't reinvent the wheel."

- AWS 为工程师提供了大量托管服务，涵盖计算、存储、数据库、缓存、消息队列、搜索、监控、CDN 等各个层面
- 使用托管服务的核心好处：**专注工程和业务问题，而不是运维和硬件问题**
- **Netflix、Airbnb 等大公司**都在 AWS 上运行，以避免操心"太阳底下的一切问题"
- **初创公司和中型公司**自己管理服务器通常没有意义，优先选择云托管方案
- **例外**：Zerodha 是一个反例（有极强的技术团队），但这不是普遍情况
- 现代云服务已经非常成熟，**自己管理基础设施的必要性越来越低**
