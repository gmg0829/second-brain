# What is an API Gateway?

**视频ID**: RbMxB_Cyx6A
**频道**: Gaurav Sen
**原始URL**: https://www.youtube.com/watch?v=RbMxB_Cyx6A

## 内容概要

本视频深入探讨了API网关的核心概念、工作原理以及在分布式系统中的关键作用，并通过AWS的实际架构案例说明了API网关如何与DNS和CDN协同工作。

API网关是位于客户端设备和内部微服务之间的服务器，其核心职责是将内部服务的API安全地暴露给外部世界。在系统架构中，数据库在最右端，移动端和桌面客户端在最左端，而API网关居于中间位置，连接Payments、Posts等内部微服务。微服务不应该直接与外部世界通信——通过API网关可以提取通用逻辑并增加安全层。

API网关提供六大核心功能。认证与授权：在请求进入时验证用户是否有权访问特定服务，认证逻辑是跨服务通用的，可以提取到网关层。请求转换：客户端发送通用JSON请求，网关根据目标服务需求进行数据转换和格式化。请求验证：在请求到达目标服务前进行格式和内容校验，验证失败直接返回，无需消耗目标服务资源。限流：防止DDoS攻击或客户端bug导致的请求洪泛，可以限制单个用户的请求速率。请求路由：根据URL路径和参数将请求路由到正确的微服务，客户端只需知道网关地址，无需关心具体服务位置。负载均衡：当某个服务有多个实例运行时，网关决定将请求发送到哪个实例，可以根据最少负载或轮询等策略分配请求。

客户端访问API网关的完整流程涉及DNS和CDN。当用户在浏览器输入域名时，DNS服务器将域名（如api.integrity.io）解析为IP地址。CDN（内容分发网络）位于网关之前，承载90%的静态内容流量——图片、视频、静态网页等，CDN节点分布全球，物理距离近的节点响应更快。AWS的典型架构是：Route 53负责DNS解析，CloudFront作为CDN，S3作为文件存储，API Gateway作为统一入口。

Gaurav分享了一个真实的"每周重启"案例。旧系统中每当某个内部服务部署新版本时，API网关都需要重启以加载新的API契约。这导致工程师们每周花费25%的时间在服务维护和重启上。最终的解决方案是采用客户端库和版本化管理——每个服务发布客户端库到git，其他服务通过依赖版本自动获取最新契约，无需网关重启。

## 核心观点

- API网关是客户端与内部微服务之间的唯一入口，实现横切关注点的集中化管理
- API网关的六大核心功能：认证授权、请求转换、请求验证、限流、路由、负载均衡
- 客户端只需知道网关地址，网关负责服务发现和请求路由，客户端无需维护服务地址列表
- CDN承载90%的静态内容流量，大幅减少对API网关和后端服务器的请求压力
- 不要在API网关堆积过多逻辑，当网关变得过于复杂时应将功能提取到独立服务（如Sidecar模式）
- 微服务契约变更不应触发网关重启，应通过版本化客户端库实现解耦
- 初创公司可以从简单的EC2实例开始，随着业务增长逐步引入托管服务，而非一开始就构建完整的微服务架构

## 关键术语

- **API Gateway（API网关）**: 位于客户端与内部服务之间的服务器，作为所有API请求的统一入口
- **Authentication（认证）**: 验证用户身份的过程
- **Authorization（授权）**: 决定用户是否有权访问特定资源的决策过程
- **Request Transformation（请求转换）**: 网关将客户端通用格式转换为目标服务所需格式的过程
- **Rate Limiting（限流）**: 限制单用户请求速率，防止DDoS攻击或资源滥用
- **DNS（域名系统）**: 将域名映射到IP地址的系统，如Route 53
- **CDN（内容分发网络）**: 全球分布的缓存服务器网络，用于加速静态内容分发，如CloudFront
- **Sidecar模式**: 将横切关注点（如限流、日志）部署为独立进程，与主服务协同工作的设计模式
- **Service Mesh（服务网格）**: 微服务间通信的基础设施层，可替代集中式API网关

## 关键语录

> "API网关在客户端和内部微服务之间。你不希望这些微服务直接与外部世界通信——你需要一个'守卫'来提取通用逻辑并增加安全层。"

> "请求路由的好处是：客户端不需要知道具体服务地址，不需要进行DNS查找，不需要根据不同请求切换服务器。客户端只知道一个服务器——API网关，网关会弄清楚请求该去哪里。"

> "真实案例：每次内部服务部署新版本，API网关都需要重启。这导致工程师每周花费25%的时间在服务维护和重启上——这是不可接受的。解决方案是采用版本化客户端库，服务间通过依赖版本自动协调，而非紧耦合到网关。"

> "很多初创公司和中型公司现在直接采用服务网格（Service Mesh）。更有趣的是，很多公司直接从单体架构开始——'我不需要完整的API网关，只需要一个EC2实例，其他都交给AWS托管或放在同一个服务里。'"
