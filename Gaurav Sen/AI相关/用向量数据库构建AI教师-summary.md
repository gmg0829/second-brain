## 内容概要

本视频分享了Gaurav Sen如何为自己的创业项目InterviewReady构建AI教学助理的完整方案。视频从问题出发——学生在观看视频课程时有疑问希望能即时获得回答，传统方案是雇助教（昂贵且响应慢），于是他转向使用向量数据库+RAG（检索增强生成）模式构建AI助手。核心方案是：先将视频转录为文本存入向量数据库，当用户提问时，通过向量相似性搜索找到最相关的多个视频内容，再将这些内容作为上下文提供给ChatGPT生成回答。视频详细介绍了向量数据库的工作原理（NSW算法、聚类）、技术选型（Neon Serverless Postgres + pg_vector）、以及RAG的具体实现流程。

## 核心观点

### 一、问题背景与方案选择

**InterviewReady的痛点**：
- 平台有视频课程、PDF下载，学生学习中有疑问
- 理想状态：用户登录后能即时获得回答

**两种方案的对比**：

| 方案 | 成本 | 质量 | 速度 |
|------|------|------|------|
| 雇请助教 | 昂贵（薪资+培训） | 不稳定 | 慢（可能等24小时） |
| **纯ChatGPT API** | 低（按token计费） | **可能 hallucinate** | 即时 |
| **向量数据库+RAG** | 低（一次存储，多次查询） | **基于真实内容** | 即时 |

**关键洞察**：直接调用ChatGPT API而不提供上下文，回答质量很差（hallucination问题严重）。解决方案是**用向量数据库找到相关内容，再让GPT基于这些内容生成回答**。

### 二、向量数据库的核心原理

**核心能力**：给定一个对象，找到所有相似对象

**如何将文本表示为向量**：
- 每个视频转录 = n维空间中的一个点
- n维 = 视频涉及的各个术语/概念
- 维度示例：
  - x轴 = 视频长度
  - y轴 = "系统设计"术语出现频率
  - z轴 = "底层设计"术语出现频率（用颜色辅助表示）

**内部算法：Navigable Small World (NSW)**
- 5000个向量 → 聚类成50个簇（每簇约100个向量）
- 每个簇有一个**代表向量（Representative Vector）**
- 查询时：不是逐个比较5000个向量，而是**先比较50个代表向量**，锁定目标簇后再精确查找
- 时间复杂度从O(n)降到O(log n)级别

**向量相似度计算**：向量数据库提供API，无需自己实现余弦相似度等计算

### 三、技术选型与实现

**技术栈选择**：
| 组件 | 选择 | 理由 |
|------|------|------|
| 向量数据库 | **Neon Serverless Postgres** (pg_vector) | Postgres生态好、开源、有版本历史管理 |
| 语音转文本 | AWS Transcribe | 便宜、效果够用 |
| LLM | GPT (OpenAI API) | 易用、API成熟 |
| 后端语言 | Go | — |

**为什么选Neon**：
1. 代码开源，可审计内部算法（如NSW的具体实现）
2. 支持**版本历史（Timeline/Branching）**——这对AI应用很关键：
   - AI模型迭代时，需要保证"相同代码+相同数据=相同结果"
   - 需要能回溯历史版本的数据
3. Serverless模式，无需手动管理AWS实例

### 四、RAG（检索增强生成）完整流程

```
用户提问
    ↓
向量数据库相似性搜索（基于用户问题）
    ↓
找到最相关的N个视频/文档（如：视频1, 6, 8, 10）
    ↓
OpenAI API：回答此问题，请参考文件1, 6, 8, 10的内容
    ↓
GPT基于提供的上下文生成回答
    ↓
返回给用户
```

**实际效果**：询问"What is load balancing?"，系统找到相关视频后，GPT给出了基于课程内容的准确回答。

**补充机制**：
- AI回答后，管理员可以审核质量
- 可选择删除AI回答、亲自回复，或让AI重新生成
- 用户无需等待24小时，即时获得回答

## 关键术语

| 术语 | 解释 |
|------|------|
| RAG (Retrieval Augmented Generation) | 检索增强生成，结合向量搜索和LLM生成答案的技术 |
| Vector Database | 向量数据库，存储高维向量表示的文本/内容，支持相似性搜索 |
| NSW (Navigable Small World) | 可导航小世界算法，用于高效相似性搜索 |
| pg_vector | Postgres的向量索引扩展 |
| Embedding | 将文本/内容转换为高维向量表示的过程 |
| Semantic Search | 语义搜索，基于内容含义而非关键词匹配来查找相关内容 |
| Neon Serverless | 基于Postgres的Serverless数据库服务 |
| Branching (Version History) | 分支/版本历史，数据库支持数据版本回溯 |
| Token | GPT API计费单位 |
