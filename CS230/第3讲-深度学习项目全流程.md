# Stanford CS230 第3讲：深度学习项目全流程

## 核心观点

深度学习项目与传统软件工程的本质区别：**代码可控，但数据不可控**。数据分布的丰富性使得我们无法预知模型会遇到什么问题，必须通过迭代试错来发现和解决。

## 项目全流程

```
问题定义 → 数据收集 → 模型设计 → 训练 → 评估 → 部署 → 监控维护
```

### 1. 数据收集（Data Collection）

**速度优先原则**：建议用 1-2 天快速获取数据，哪怕质量不够高。快速迭代比完美数据更重要。

常见数据采集策略：
- 众包平台（Zoom 等视频服务）
- 内部摄像头采集（员工知情同意）
- 校园高人流量区域（食堂等）

> **案例**：Andrew Ng 曾让团队用 48 小时头脑风暴如何快速采集数据，发现快速迭代比花数月打磨数据集更高效。

### 2. 模型训练与迭代

**经验主义开发流程**：先构建 → 看效果 → 发现问题 → 修复 → 重复。

- **误差分析（Error Analysis）**：通过分析模型失败案例，决定下一步是改模型架构还是优化数据。
- **Data-centric AI**：系统性工程化数据来提升 AI 系统性能，比盲目采集更高效。

> **关键洞察**：数据不是越多越好，而是要有针对性地获取模型真正欠缺的子类别数据。

### 3. 部署与边缘计算

以人脸识别门禁系统为例：
- **视觉活动检测（VAD）**：先用简单规则（如像素变化率）判断是否有人，节省云端计算资源。
- **级联优化**：简单方法快速过滤 + 复杂模型精准确认。

> **案例**：实现后发现视频帧中部分画面模糊，通过筛选高分辨率帧显著提升了识别准确率——这类发现只有实际部署后才能获得。

### 4. 监控与维护（Monitoring & Maintenance）

警惕 **数据漂移（Data Drift）** 和 **概念漂移（Concept Drift）**：
- 季节变化（冬天戴围巾、夏天戴墨镜）
- 地域差异（加州训练的自动驾驶模型到德州失效）

**实践建议**：
- 部署多个仪表盘监控指标（延迟、误识率、重新认证频率等）
- 团队头脑风暴所有可能出错的情况，提前设计监控告警
- 简单模型（如像素变化阈值）对分布变化更鲁棒；深度模型更脆弱但精度更高

### 5. 常见陷阱

| 陷阱 | 应对 |
|------|------|
| 认为"测试集好 = 产品好" | 聚焦实际应用效果，而非仅关注指标 |
| 盲目采集"更多数据" | 通过误差分析定位真正短板，针对性补充 |
| 忽视数据分布变化 | 建立持续监控和模型更新机制 |
| 过度工程化 | 快速原型验证，逐步迭代 |

## 总结

> 构建深度学习系统 = **代码 + 数据 + 迭代速度**。在不了解数据全貌的情况下，快速构建→实验验证→发现问题→针对性修复，是驱动项目进展的核心方法论。
