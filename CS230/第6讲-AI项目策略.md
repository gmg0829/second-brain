# Stanford CS230 第6讲：AI项目策略

## 核心观点：速度决定成败

构建AI系统时，**开发流程的效率**往往比算法本身更能决定性能上限。一个熟练团队可能1个月完成的项目，经验不足的团队需要1年——这是真实的10倍差距。

## 案例一：语音唤醒设备（Wake Word Detection）

以"Robert, turn on"语音控制灯为例，Andrew Ng展示了一个真实AI项目的迭代过程：

**阶段1：快速验证**
- 先做文献调研（优先于从头实现）
- 利用开源代码快速搭建原型
- 咨询专家（发邮件给论文作者，10分钟可能带来巨大突破）

**阶段2：数据收集**
- 真实数据 > 合成数据（天然数据少一个需要担心的变量）
- 可用TTS合成，但需注意声音多样性不足的问题
- 收集背景噪音 + 干净人声叠加 = 合成更多训练样本

**阶段3：常见坑与对策**
| 问题 | 解决思路 |
|------|---------|
| 数据不平衡（正例:负例=1:30）| 复制正例 / 调整损失函数权重 |
| 过拟合 | 正则化 / 增加数据多样性 |
| 合成数据分布不匹配 | 确保测试集用真实数据 |

## ML开发 = 调试，而非传统开发

传统软件：写规格 → 实现 → 大部分能work
ML系统：你永远不知道下一步会出什么错

健康的迭代节奏：
- **晚间**：提交训练任务（4小时或更长）
- **次日**：看结果 → 错误分析 → 下午写代码修复
- **傍晚**：再次提交，循环往复

每24小时修复一个问题，就能快速推进。

## 案例二：AI深度研究智能体（Deep Researcher）

多阶段Pipeline示例：
```
用户Query → 搜索词生成 → 网页搜索 → 页面筛选 → 报告撰写
```

**关键：找到瓶颈组件**
Andrew Ng建议用电子表格做错误分析：
- 取10-100个失败案例
- 标注每个失败出在哪个环节（搜索词？搜索结果？页面选择？写作？）
- 统计各环节失败频率 → 确定下一步聚焦哪里

团队Spend几小时做错误分析，可能节省几周走错方向。

## 战略心得

1. **先跑通，再优化**：快速做出能工作的系统，远好于花大量时间设计"完美"架构
2. **数据优先级**：天然数据优先，合成数据作为后续补充手段
3. **系统化错误分析**：这是ML团队最重要的生产力工具
4. **速度的复利效应**：比竞争对手快2倍，可能意味着产品性能大幅领先

> 机器学习开发本质上是**高度结构化的调试过程**，而非传统工程。
