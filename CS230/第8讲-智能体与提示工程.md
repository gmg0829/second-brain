# Stanford CS230 第8讲：智能体、提示工程与RAG

## 课程概述

本讲聚焦于**超越基础 LLM** 的应用层优化，探索如何在实际业务场景中构建可靠的 AI 系统。核心议题包括：提示工程、RAG（检索增强生成）、智能体工作流、多智能体系统，以及评估方法。

---

## 一、增强 LLM 的挑战与机遇

基础预训练模型存在多重局限：**领域知识缺失**（如农业病害识别）、**知识时效性不足**（无法追踪新趋势）、**特定任务精度不够**（企业级应用要求高保真、低延迟）、**可控性差**（2016 年微软 Tay 机器人事件即为典型）、以及**上下文窗口有限**（"大海捞针"问题）。

提升路径分为两个维度：**纵向**——升级基础模型（GPT-3.5 → GPT-4 → GPT-4o）；**横向**——通过提示工程、智能体工作流、RAG 等方法最大化现有模型性能。本课程重点聚焦横向维度。

---

## 二、提示工程（Prompt Engineering）

### 核心方法

| 方法 | 说明 |
|------|------|
| **Zero-shot** | 直接下达任务指令，无示例 |
| **Few-shot** | 在提示中嵌入 2-3 个示例，对齐任务预期 |
| **Chain-of-Thought** | 引导模型逐步思考，"step by step, do not skip" |
| **Chaining** | 将复杂任务拆分为多步骤链式提示，独立调试各步骤 |
| **Act as X** | 指定角色行为（"act like a renewable energy expert"），效果显著 |
| **Self-critique** | 让模型先输出，再自我批判，迭代优化 |

### 研究洞察

BCG 咨询研究揭示：**JAG Frontier**——AI 在某些任务上显著提升人类绩效，在另一些任务上反而降低绩效（如人类过度依赖 AI 而疏于审核）。 consultants 的工作模式分两类：**Centaurs**（完整委托 AI 完成大任务）与 **Cyborgs**（人机高频来回交互）。提示工程技能应成为每个人的通用能力，而非专门的职业。

## 三、微调（Fine-tuning）

对微调持保守态度，原因：

1. **需要大量标注数据**
2. **容易过拟合**，丧失通用能力（案例：Slack 微调后模型学会"假装工作"而非执行指令）
3. **成本高、周期长**，新模型发布后可能被直接超越

**适用场景**：任务需高精度、特定领域语言（法律、科学写作）。大多数场景优先选择提示工程 + RAG。

## 四、RAG（检索增强生成）

### 为什么需要 RAG

- **知识时效性**：模型训练数据有截止日期，无法追踪最新趋势
- **减少幻觉**：医疗、教育、法律等领域不允许虚构内容
- **可溯源性**：用户需看到答案的原始来源

### 工作流程

```
用户查询 → 嵌入用户 query → 向量数据库检索 → 拼接相关文档至提示 → LLM 生成答案
```

### 关键技术

- **Chunking**：大文档按章节/段落拆分，分别存储向量，提升检索精度
- **HyDE（Hypothetical Document Embeddings）**：用模型根据用户问题生成"假文档"，再与向量库匹配——解决 query 与文档表述风格不匹配的问题

### RAG 的长期价值

即使上下文窗口足够大，RAG 仍有价值：1）**延迟**——不必每次都读取全部文档；2）**实时性**——文档更新即时生效；3）**可溯源**——这是法律、医疗等领域的硬需求。

## 五、智能体 AI 工作流（Agentic AI Workflows）

### 定义

Andrew Ng 提出：**智能体工作流** = 多步骤流程 + 工具调用 + 外部资源 + API 调用，最终组合为一个可执行工作流。"Agent" 一词被过度使用，用工作流描述更为准确。

### 基础架构组件

| 组件 | 说明 |
|------|------|
| **Prompt** | 任务指令 |
| **Memory** | 工作记忆（快速访问）+ 归档记忆（慢速访问） |
| **Tools** | API、数据库查询、代码执行 |
| **Resources** | CRM、文档等外部数据源 |

### 自立程度分级

1. **低自主**：硬编码步骤顺序，agent 按预设流程执行
2. **中自主**：硬编码工具集，agent 自行决定调用顺序
3. **高自主**：agent 可自主创建工具、编写代码、调用任意 API

### MCP（Model Context Protocol）

Anthropic 提出的标准化协议：agent 通过 MCP 客户端与多个 MCP 服务器通信，无需为每个 API 单独编写对接代码，实现更高可扩展性。

### 案例：信贷风险备忘录优化

传统流程：关系经理收集 15+ 数据源 → 信用分析师协作分析 → 撰写备忘录（20+ 小时）→ 多轮反馈。引入 GenAI 智能体后，**时间缩短 20-60%**：agent 自动分解任务、调度专家智能体、汇总结果，人类仅需审核与反馈。组织变革仍是最大难点（需 10-20 年）。

## 六、评估方法（Evals）

### 评估维度

| 维度 | 方法 |
|------|------|
| **客观指标** | 自动比对（如订单 ID 是否正确提取） |
| **主观指标** | 人工评分 / LLM as Judge（通过 rubric 打分） |
| **端到端** | 用户满意度调查 |
| **组件级** | 分步排查（数据库查询 → 邮件起草 → 发送，各环节独立调试） |
| **定量** | 成功率、延迟、吞吐量 |
| **定性** | 错误分析、幻觉检测、语气评估 |

### LLM as Judge 用法

- **Pairwise comparison**：给出两个答案，让 LLM 判断哪个更好
- **Single-answer grading**：按 rubric（1-5 分）打分
- 可结合 Few-shot 为 LLM 提供评分示例

## 七、多智能体系统（Multi-Agent Workflows）

### 适用场景

- **并行化**：多个独立任务同时执行（如同时查询机票、酒店、景点）
- **智能体复用**：一个设计智能体可供营销、产品等多团队共用
- **特殊化调试**：可单独调试某个专业智能体，再组合整体系统

### 组织模式

- **层级式（Hierarchical）**：Orchestrator Agent 作为统一入口，分发任务给专业 Agent
- **扁平式（Flat）**：Agent 间点对点通信，协同完成复杂任务

### 案例：智能家居

可构建：气候控制 Agent、照明 Agent、安防 Agent、能源管理 Agent、娱乐 Agent、通知 Agent，以及顶层 Orchestrator。层级式适合家居场景——用户只需与 Orchestrator 对话，由其协调各专业 Agent。

## 八、未来趋势

1. **架构搜索**：Transformer 之后，下一代架构突破可能在 10x 降低计算与能源需求
2. **多模态融合**：文本 + 图像 + 音频 + 视频互通提升，机器人为终极形态
3. **多方法协同**：监督学习、自监督学习、强化学习、RAG 等方法融合（类似婴儿学习方式）
4. **半衰期压缩**：AI 技术变更极快，课堂目标是建立广度视野，按需深入
