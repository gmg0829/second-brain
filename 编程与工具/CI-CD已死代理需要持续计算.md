## 核心观点

传统的 CI/CD 系统是为人而设计的——人类开发者每周最多提交一到两个代码差异。但当数千个自主代理（AI Agent）开始持续提交 PR 时，一切都崩溃了。

> **Madison Faulkner**："我们正处于一个令人难以置信的峰值期。GitHub 的活动已经完全疯狂了。"

---

## 为什么 CI/CD 已死？

### 传统 CI/CD 的工作模式

1. 人类开发者提交一个（或少数几个）diff
2. 同事花时间 review
3. 运行 GitHub Actions：构建 → 测试 → 部署
4. 修复失败的测试用例
5. 迭代

这种方式下，代码生成便宜，但工作流程缓慢。

### 代理规模下的噩梦

```
┌─────────────────────────────────────────────────────────┐
│  人类模式                 vs        代理模式            │
├─────────────────────────────────────────────────────────┤
│  1-2 个 PR/周              数千个短生命周期分支          │
│  本地缓存通常温热           冷缓存、无共享状态           │
│  合并时间可预测             所有版本合并变得不可能       │
└─────────────────────────────────────────────────────────┘
```

**具体问题**：

- **Runner 饱和**：大量并发任务抢占资源
- **冷 Docker 构建**：每个分支都从零开始构建
- **缓存失效**：大量相似代码同时拉取，缓存命中率极低
- **合并队列序列化**：PR 队列变成类似数据库锁的串行化瓶颈

## GitHub 活动数据

演讲中展示了 GitHub 活动的惊人数据：
- 白线 = 实际提交数
- 最近几个月呈现"令人难以置信的 spike"

这说明 AI 辅助编程的普及速度远超基础设施的承载能力。

## 解决方案：持续计算（Continuous Compute）

### 核心思路

用缓存作为编排层，通过硬件和软件协同设计来加速现有的 GitHub Actions 等 CI/CD 基础设施。

### 新架构设计

```
                    ┌─────────────────┐
                    │   Intent & Plan │
                    │   (意图与计划)   │
                    └────────┬────────┘
                             │
                    ┌────────▼────────┐
                    │   Agent Harness │
                    │   (代理线束循环) │
                    │  cursor/Claude/ │
                    │  Windsurf/其他   │
                    └────────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
     ┌────────▼────────┐ ┌────▼────┐ ┌──────▼──────┐
     │  检出已知 Commit │ │ 构建    │ │   运行测试   │
     │  (不变式检查)   │ │         │ │ (内部验证)   │
     └────────┬────────┘ └────┬────┘ └──────┬──────┘
              │              │              │
              └──────────────┴──────────────┘
                             │
                    ┌────────▼────────┐
                    │   Human Review   │
                    │   (人类确认)     │
                    └────────┬────────┘
                             │
                    ┌────────▼────────┐
                    │   Pre-Merge     │
                    │   Queue         │
                    │   (预合并队列)  │
                    └────────┬────────┘
                             │
                    ┌────────▼────────┐
                    │    Repository    │
                    │    (分类账/仓库)  │
                    └─────────────────┘
```

### 关键变化

| 传统模式 | 新模式 |
|---------|--------|
| PR 作为工作单元 | Intent & Plan 作为起点 |
| 人类 Review | AI Agent Review（安全 LLM、API 合规 LLM） |
| 阶段式验证 | 持续验证（每次迭代都经过验证） |
| 串行化合并 | Pre-Merge 队列 + 语义分组 |
| 独立 CI | CI 原则融入循环 |

---

## 代理工作循环的进化

### 当前状态（人类在环）

```
Intent → Agent Loop → Internal Validation → Human Review → Merge Queue → Repo
```

### 未来方向（数周至数月内）

```
Intent → Agent Loop → Internal Validation → Agent Review → Pre-Merge Queue → Repo
                                              ↑
                                    其他 AI Agent 提供反馈
                                    (安全、合规、API 合规)
```

**关键特征**：

- **快速推理**：代码生成和验证都必须极快（不能花 15-45 分钟跑测试）
- **有状态环境**：Memory 和 State 很重要，从零启动会延迟整个循环
- **Pre-Merge 队列**：并行运行在代码库相同部分的大量变更需要协调以保证串行化
- **多代理协同**：安全 LLM、API 合规 LLM 等多代理在循环中提供反馈

---

## CI 的角色转变

> **Hugo Santos**："CI 仍然重要，但它已经转移了。"

### 仍然需要的 CI 原则

- **不变式检查**：确保从已知、可信的代码版本出发
- **合规性保证**：防止未经审核的代码进入仓库
- **持续验证**：每次迭代都经过验证，而非作为独立阶段

### 不再需要的 CI 功能

- 引导不同变更的协调
- 确保不同测试通过才能提交变更
- 这些都需要纳入整体循环中

---

## 未来展望：Multiverse 模式

如果这个过程变得极快，可能会进入 **Multiverse（多宇宙）模式**：

```
传统模式：Intent & Plan → 最新 Commit（唯一的）
                    ↓
Multiverse：Intent & Plan → 多个并行 Commit
                    ↓
              探索多个候选版本
              同一计划下的多路径尝试
```

这需要极高的内部循环速度，因为所有同时探索的候选版本都会消耗资源。

---

## Governance（治理）的提升

治理并没有消失，而是**提升到了 Harness 层面**：

- 代码格式化
- 团队规范遵循
- 合规性检查
- 所有这些都被编码到 Harness 中，持续引导代理行为

---

## 核心启示

1. **代码生成已经很便宜，工作变得更加连续**，这迫使评估进入内循环
2. **人类曾是代理**，有明确的意图和计划，现在 AI 正在接管这个角色
3. **合并时间是关键瓶颈**，当机器运行时锁时间短但频率高
4. **需要新架构**：不是渐进式改进，而是根本性的范式转变
5. **CI/CD 的原则仍然有效**，但实现方式从独立阶段转变为持续循环

---

## 总结

我们正在从**人类驱动的 CI/CD** 转向**代理驱动的持续计算**。这不是关于删除 CI/CD，而是关于重新定义它在 AI 原生开发世界中的角色。缓存将成为编排层，代理循环将取代 PR 流程，而人类将从代码 reviewer 转变为 intent approver。

> **"这是一个疯狂的世界，我们需要为之做好准备。"** —— Hugo Santos
