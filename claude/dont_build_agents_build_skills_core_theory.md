# 不要构建 Agent，而要构建技能（Skills）
**核心理论提炼**

> 演讲者：Barry Zhang & Mahesh Murag（Anthropic Applied AI 团队）
> 活动：AI Engineer Code Summit 2025，纽约
> 视频：[Don't Build Agents, Build Skills Instead](https://www.youtube.com/watch?v=CEvIs9y1uog)

---

## 背景：一年间的范式演进

2025 年，Anthropic 在 Agent 领域连续发布了一系列里程碑产品：

```
MCP 成为标准  →  Claude Code 发布  →  Claude Agent SDK  →  Agent Skills
   （连接层）        （第一个编程 Agent）    （生产就绪运行时）     （专业知识层）
```

这条时间线揭示了一个核心判断：**架构在收敛，缺失的不是智能，而是专业知识。**

---

## 核心问题：Agent 的"专业知识鸿沟"

### 旧思维的误区

过去的假设：不同领域的 Agent 长相迥异，每个领域都需要独立的工具集和脚手架 → 为每个用例分别构建专用 Agent。

### 新洞见：代码是通用接口

Claude Code 的构建经历让 Anthropic 意识到：

> "代码不只是一个用例，而是通向数字世界的通用接口。"

一个通用 Agent 通过代码可以完成任何领域的任务：

```
金融报告生成示例：
调用 API 拉取数据  →  文件系统整理数据  →  Python 分析  →  生成文件
                    ↑
         全部通过代码完成，脚手架精简至 bash + 文件系统
```

**结论**：Agent 的底层比我们想象的更通用。真正的瓶颈不在架构，在**领域专业知识**。

### 高智商通才 vs 领域专家

> "谁来帮你报税？是 Mahesh——300 IQ 的数学天才，还是 Barry——经验丰富的税务专员？我每次都选 Barry。我不需要 Mahesh 从第一性原理推导 2025 年税法，我需要领域专家稳定地执行。"

当前的 Agent 就像 Mahesh：
- ✅ 才华横溢，能从零推导复杂问题
- ❌ 缺乏领域专知，无法吸收已有的机构经验
- ❌ 不会随时间自动积累和学习

## 核心理论一：Skills 的本质定义

### 什么是 Skills？

> "Skills 是为 Agent 打包可组合程序性知识的、有组织的文件集合。"

**简单来说：Skills 就是文件夹。**

这个"简单"是刻意为之的：

```
典型 Skill 目录结构：
skill-name/
├── SKILL.md          ← 核心说明文档（含 front matter 元数据）
├── reference-doc.md  ← 参考资料
└── helper-script.py  ← 可执行脚本（作为工具）
```

### Skills 的三大设计原则

**① 人人可用**
任何人——不论是人类还是 Agent——只要有一台电脑，就能创建和使用 Skills。
非技术人员（财务、法务、招聘、财会）已经在生产中构建 Skills，这是早期验证。

**② 兼容已有工作流**
- 用 Git 做版本控制
- 放入 Google Drive 共享
- 打包成 zip 传递给团队
- 文件这个原语已经使用了几十年，无需引入新范式

**③ 渐进式加载，保护上下文窗口**

```
Agent 启动时：只看到 SKILL.md 的 front matter 元数据（极简摘要）
                        ↓
         Agent 决定需要使用该 Skill 时
                        ↓
         完整加载 SKILL.md + 目录 + 相关资源
```

这个机制使得同时装载数百个 Skills 成为可能，而不会耗尽上下文窗口。

## 核心理论二：脚本优于传统工具

### 传统工具（Tool）的缺陷

| 问题 | 说明 |
|------|------|
| 描述模糊 | 指令写得差、存在歧义 |
| 不可修改 | 模型遇到困难时无法调整工具本身 |
| 占用上下文 | 工具定义始终存在于上下文窗口中 |

### 代码脚本作为工具的优势

```
传统工具：静态描述，模型只能调用，无法改进
代码脚本：自说明、可修改、按需从文件系统加载
```

具体实践：Claude 曾反复为幻灯片样式编写相同的 Python 脚本 → 将脚本保存进 Skill → 未来直接调用，既一致又高效。

**关键区别**：代码是"活的工具"——可被 Agent 理解、修改、进化；传统工具描述是"死的声明"——遇到问题只能靠模型强行应对。

## 核心理论三：通用 Agent 的新兴架构

### 架构收敛公式

```
┌─────────────────────────────────────────────────────────┐
│                  通用 Agent 架构                         │
│                                                         │
│   ┌──────────────┐                                      │
│   │  Agent Loop  │  ← 管理模型上下文，控制 token 进出   │
│   └──────┬───────┘                                      │
│          │ 运行于                                        │
│   ┌──────▼───────┐                                      │
│   │ 运行时环境   │  ← 文件系统 + 代码读写能力            │
│   └──────┬───────┘                                      │
│          ├─────────────────────┐                        │
│   ┌──────▼───────┐   ┌────────▼────────┐               │
│   │  MCP 服务器  │   │   Skills 库     │               │
│   │（外部连接层）│   │（领域专业知识层）│               │
│   └──────────────┘   └─────────────────┘               │
└─────────────────────────────────────────────────────────┘
```

### MCP 与 Skills 的分工

| 层 | 职责 | 类比 |
|----|------|------|
| **MCP 服务器** | 连接外部世界（API、数据库、服务） | 网络接口 |
| **Skills 库** | 提供领域专业知识，按需加载 | 专业手册 |
| **两者结合** | 进入新垂直领域的最短路径 | — |

> "今天，让 Agent 获得新领域的能力，可能只需要为它配备正确的 MCP 服务器和正确的 Skills 库。"

Anthropic 自身已经用这套架构快速落地金融服务和生命科学两个新垂直领域。

## 核心理论五：Skills 即持续学习的载体

### 从知识使用到知识创造

Skills 被设计为"持续学习"的具体实现步骤：

```
第 1 天：Claude 使用你的 Skills 执行任务
   ↓
给予反馈，传递机构知识
   ↓
Claude 将新知识写入新的 Skill
   ↓
第 30 天的 Claude 远比第 1 天更了解你的团队
   ↓
团队中所有人的 Agent 共同进步
```

### 标准化格式的核心价值

> "当你开始使用 Claude 时，这个标准化格式提供了一个重要保证：任何 Claude 写下的东西，都可以被未来版本的自己高效使用。这让学习真正变得可迁移。"

- Claude 可以**即时获取**新能力
- 可以**按需进化**已有能力
- 可以**丢弃**已经过时的能力

### 复利效应

```
个人层面：  工作越久，Claude 越了解你的偏好
团队层面：  一人构建的 Skill，团队所有 Agent 受益
组织层面：  新成员入职，Agent 已了解组织文化和规范
社区层面：  他人发布的 Skill，提升所有人的 Agent 能力
```

## 核心理论六：计算机栈类比

这是整个演讲最深刻的理论框架：

| 计算机栈 | AI Agent 栈 | 特征 |
|---------|------------|------|
| **处理器** | **基础模型** | 需要巨额投资，蕴含无限潜力，但单独存在没有价值 |
| **操作系统** | **Agent 运行时** | 编排资源，让处理器/模型真正可用；少数公司在构建 |
| **应用软件** | **Skills** | 数百万开发者编码领域专知；这里才是真正的价值所在 |

> "少数公司构建了处理器和操作系统，但数百万开发者构建了编码领域专业知识和独特观点的软件。我们希望 Skills 能为每个人打开这一层。"

**战略含义**：Skills 层是 AI 时代的"应用软件"，是普通开发者和非技术人员最能贡献价值的层次。

## Skills 的未来进化方向

### 1. 像软件一样对待 Skills

- **测试与评估**：确保 Agent 在正确的时机、为正确的任务加载技能
- **质量度量**：衡量配备 Skill 的 Agent 输出质量是否达标
- **版本管理**：技能演化时有清晰的血缘追踪

### 2. Skills 之间的依赖与组合

- Skills 能显式依赖其他 Skills
- Skills 能依赖 MCP 服务器
- Skills 能依赖 Agent 运行时中的包和依赖
- 组合多个 Skills，使 Agent 能产生更复杂的领域行为

## 总结：核心理论体系

```
                核心问题
        Agent 智能有余，专业知识不足
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
     代码是通用接口         Skills 是解法
   （Agent 底层更通用）   （领域知识的载体）
          │                   │
    一个通用 Agent       ┌────┴────┐
    胜过多个专用 Agent   │         │
                      设计原则   架构位置
                      · 文件夹    · MCP 提供连接
                      · 渐进加载  · Skills 提供专知
                      · 人人可建  · 运行时按需加载
                                  │
                              长期价值
                         持续学习 + 复利增长
                         个人→团队→组织→社区
```

**一句话总结**：停止为每个领域重复构建 Agent，转而构建一个通用 Agent 加上一个不断丰富的 Skills 库——Skills 是 AI 时代的应用软件，是领域专业知识的标准化载体，也是实现持续学习的最小可行单元。
