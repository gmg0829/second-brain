## 核心内容 / Core Content

### 什么是产品感？/ What is Product Sense?

**Alex 的比喻**：

> "就像看到学生走进教室，他开始写东西，铅笔断了。我跑过去，把备用铅笔放在他桌上，无需言语——问题解决。"

这就是**产品感**：预测用户需求，在问题发生前解决。

### 产品感的三个维度 / Three Dimensions of Product Sense

1. **机会识别** - 发现数据中的机会
2. **产品评估** - 评估现有产品表现
3. **用户对齐** - 将 AI 开发与用户需求对齐

---

## 关键洞察 / Key Insights

### 1. 不要为技术找问题 / Avoid Solution in Search of Problem

**问题**：
- 新技术出现时，容易"拿着锤子找钉子"
- "ChatGPT 很火，不用它就是落伍"

**建议**：
- 使用正确的工具解决正确的问题
- 决策树、逻辑回归在很多场景下依然有效
- 长期思维 > 追逐热点

### 2. 数据驱动的机会识别 / Data-Driven Opportunity Identification

**示例**：
- 在线厨具店：用户手动把食品加工器和削皮器加入购物车
- **洞察**：这两个产品应该捆绑销售

### 3. 用户视角 / User Perspective

**核心观点**：
> "如果你设计一个篮球，你只想着篮球，那就错了。你应该想着篮球运动员。"

### 4. 与客户协作 / Client Collaboration

**模式**：
- **KUNGFU.AI 引导 + 客户驱动**
- 而非反过来的"技术驱动"

**实践**：
- 定期 SME（主题专家）访谈
- 每周例会更新进度
- 异步沟通保持反馈

## 产品评估指标 / Product Evaluation Metrics

### 外部指标

| 指标 | 描述 |
|------|------|
| 销售数据 | 产品需求如何 |
| 续订率 | 用户是否持续使用 |

### 内部指标

| 指标 | 描述 |
|------|------|
| 耐用性 | 产品能使用多久 |
| 稳定性 | 是否可靠 |
| 用户测试 | 用户体验如何 |

## AI 产品的特殊考虑 / AI Product Considerations

### 概率性特征 / Probabilistic Nature

**与传统软件的差异**：
- 传统软件：确定性输出
- AI 产品：概率性输出，结果可能不同

**建议**：
- 使用置信区间表达不确定性
- 提前沟通"预期结果"和"预测"
- 注意：AI 产品的风险更高

### 信任与责任 / Trust & Liability

**关键问题**：
- AI 给出错误建议的后果是什么？
- 需要监控 AI 实际做什么
- 建立可观测性系统

---

## 产品感 vs 技术 / Product Sense vs Technology

### 常见错误

| 错误 | 后果 |
|------|------|
| 技术优先 | 开发不满足用户需求的产品 |
| 追逐热点 | 用 ChatGPT 解决不需要 AI 的问题 |
| 忽视数据 | 凭直觉做决定 |

### 正确方式

1. **从用户需求出发**
2. **用数据验证假设**
3. **选择合适的技术**
4. **持续迭代反馈**

## 总结 / Summary

### 产品感的核心

| 维度 | 关键问题 |
|------|----------|
| 用户现实 | 用户真正想完成什么？ |
| 机会识别 | 数据中有什么机会？ |
| 产品评估 | 产品表现如何？ |
| 技术选择 | 用什么技术最合适？ |
| 协作沟通 | 如何与客户对齐？ |

### AI 产品感的特别之处

1. **概率性思维** - 接受不确定性，用置信区间表达
2. **长期视角** - 不要追逐热点，要解决问题
3. **用户为中心** - 技术服务于用户需求
4. **持续沟通** - 与利益相关者保持密切联系
