## 核心概念 / Core Concepts

### 什么是提示工程？/ What is Prompt Engineering?

**定义：**
提示工程是与 AI 模型有效沟通的艺术和科学，通过精心设计提示来获得更好的输出。

### 为什么重要？/ Why Does It Matter?

| 方面 | 描述 |
|------|------|
| 质量 | 好的提示 = 好的输出 |
| 效率 | 减少迭代次数 |
| 控制 | 更精确地控制 AI 行为 |

## 提示工程基础 / Prompt Engineering Basics

### 1. 提示的结构 / Prompt Structure

```
┌─────────────────────────────────────┐
│         提示的基本组成                 │
├─────────────────────────────────────┤
│ 1. 任务说明 (Task Description)      │
│    → 明确告诉 AI 要做什么             │
├─────────────────────────────────────┤
│ 2. 上下文 (Context)                  │
│    → 提供背景信息                     │
├─────────────────────────────────────┤
│ 3. 示例 (Examples)                   │
│    → 输入/输出示例                    │
├─────────────────────────────────────┤
│ 4. 格式要求 (Format Requirements)    │
│    → 输出格式说明                     │
├─────────────────────────────────────┤
│ 5. 约束 (Constraints)               │
│    → 限制条件                        │
└─────────────────────────────────────┘
```

### 2. 提示的黄金法则 / Golden Rules

| 法则 | 描述 |
|------|------|
| 清晰 | 明确表达需求 |
| 具体 | 详细说明要求 |
| 结构 | 有组织地呈现 |
| 示例 | 提供具体例子 |

## 高级技巧 / Advanced Techniques

### 1. Chain of Thought (思维链)

**原理：**
让 AI 展示推理过程，提高复杂任务的准确性。

**示例：**
```
问题：如果你有5个苹果，吃了2个，又买了3个，你现在有多少个苹果？

让我们一步步思考：
1. 起始：5个苹果
2. 吃掉：5 - 2 = 3个
3. 购买：3 + 3 = 6个
答案：6个苹果
```

### 2. Few-Shot Learning (少样本学习)

**原理：**
通过提供少量示例，帮助 AI 理解任务要求。

**示例：**
```
任务：将句子改写为正式语气

示例：
- 原文：我要这个
- 正式：请给我这个

- 原文：开会时间改了
- 正式：会议时间已变更

现在改写：明天见
```

### 3. Role Playing (角色扮演)

**原理：**
给 AI 设定特定角色，获得更专业的输出。

**示例：**
```
你是一位有20年经验的资深软件架构师。
请审查以下代码的架构问题：

[代码内容]
```

### 4. System vs User Prompts

| 类型 | 描述 | 示例 |
|------|------|------|
| System Prompt | 设置 AI 的行为和角色 | "你是一位有帮助的助手" |
| User Prompt | 具体的任务请求 | "写一首关于春天的诗" |

## 实践指南 / Practical Guide

### 1. 撰写提示的步骤 / Steps to Write Prompts

| 步骤 | 行动 |
|------|------|
| 1 | 明确目标 - 要完成什么？ |
| 2 | 收集上下文 - 需要什么信息？ |
| 3 | 组织结构 - 怎么呈现最好？ |
| 4 | 添加示例 - 需要示范吗？ |
| 5 | 定义格式 - 输出要什么格式？ |

### 2. 优化提示的方法 / Ways to Optimize Prompts

| 方法 | 描述 |
|------|------|
| 迭代 | 基于输出不断改进 |
| 简化 | 去除无关信息 |
| 具体化 | 越具体越好 |
| 测试 | 多场景测试 |

## Claude 特定技巧 / Claude-Specific Techniques

### 1. 使用 XML 标签

Anthropic 推荐使用 XML 标签来组织提示：

```xml
<context>
这里提供背景信息...
</context>

<task>
这里描述具体任务...
</task>

<output_format>
这里说明输出格式...
</output_format>
```

### 2. Pre-computation (预计算)

提前思考 AI 可能需要的上下文：

```xml
<thinking>
在回答之前，让我考虑：
1. 用户真正想要什么？
2. 有什么限制条件？
3. 最佳答案应该包含什么？
</thinking>
```

### 3. Cascading Prompts (级联提示)

将复杂任务分解为多个简单提示：

```python
# 第一步：理解任务
"分析这篇文档的主要观点"

# 第二步：深入分析
"基于以上观点，提供具体例子"

# 第三步：总结
"用一句话总结整个分析"
```

## 常见错误 / Common Mistakes

### 1. 提示太模糊

```
❌ 错误：写一些关于科技的东西
✅ 正确：写一篇关于 AI 在医疗领域应用的文章，
   800字，重点讲诊断和手术
```

### 2. 缺少上下文

```
❌ 错误：解释这个概念
✅ 正确：向一个5岁的孩子解释什么是 AI，
   使用简单的比喻
```

### 3. 没有约束

```
❌ 错误：写一首诗
✅ 正确：写一首四句的七言绝句，主题是春天，
   押韵
```

### 4. 格式不明确

```
❌ 错误：给我一些建议
✅ 正确：给我5条提高工作效率的建议，
   每条不超过20字，用列表形式
```

## Anthropic 的最佳实践 / Anthropic's Best Practices

### 1. 直接清晰 / Be Direct

**原则：**
直接说出你想要什么，不要让 AI 猜测。

### 2. 使用完整句子 / Use Complete Sentences

**原则：**
用完整的句子表达，比碎片化的关键词更好。

### 3. 明确格式 / Be Specific About Format

**原则：**
清楚地说明你希望输出是什么格式。

### 4. 迭代优化 / Iterate

**原则：**
提示是迭代的，第一次不好没关系，持续改进。
