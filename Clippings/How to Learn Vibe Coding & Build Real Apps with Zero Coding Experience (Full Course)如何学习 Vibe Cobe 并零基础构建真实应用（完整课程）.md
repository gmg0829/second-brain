# What Vibe Coding Actually Is什么是氛围编码？

Let me define this precisely because there is a lot of confusion around it.让我来精确地定义一下，因为很多人对此感到困惑。

Vibe coding is building software by describing your intent to an AI model in natural language, rather than writing code syntax yourself. You explain what you want the application to do. The AI writes the code. You test the result. You describe what needs to change. The AI updates the code. You iterate until the application works.Vibe 编码是指用自然语言向 AI 模型描述你的意图来构建软件，而不是自己编写代码语法。你解释你希望应用程序实现的功能，AI 会编写代码。你测试结果，然后描述需要修改的地方，AI 会更新代码。如此反复迭代，直到应用程序正常运行。

**You are the architect. The AI is the builder.你是建筑师，人工智能是建造者。**

You decide what gets built, how it should look, how it should behave, and what constitutes quality. The AI handles the implementation - the syntax, the frameworks, the configuration files, the boilerplate, the debugging.您决定构建什么、它的外观、它的行为方式以及质量标准。人工智能负责实现——语法、框架、配置文件、样板代码和调试。

This does not mean you can be completely ignorant about how software works. You need to understand concepts - not syntax. You need to know what a database is and why you would use one, but you do not need to know how to write SQL queries. You need to know what an API is and what it does, but you do not need to memorize HTTP methods.但这并不意味着你可以完全不了解软件的工作原理。你需要理解的是概念，而不是语法。你需要知道什么是数据库以及为什么要使用数据库，但你不需要知道如何编写 SQL 查询语句。你需要知道什么是 API 以及它的作用，但你不需要记住 HTTP 方法。

**The mental model shifts from "how do I write this code" to "how do I describe what I want clearly enough that the AI writes the correct code."思维模式从“我该如何编写这段代码”转变为“我该如何清晰地描述我想要的东西，以便人工智能能够编写正确的代码”。**

And that second skill - clear description - is something every professional already practices daily when delegating work to colleagues, writing project briefs, or explaining requirements to a team.而第二项技能——清晰的描述——是每位专业人士在日常工作中都会练习的，例如将工作委派给同事、编写项目简报或向团队解释需求。

# The Biggest Myth About Vibe Coding关于氛围编码的最大误区

People think vibe coding requires an expensive setup. A powerful computer. Multiple monitors. A specific IDE. A specific operating system.人们认为 Vibe 编程需要昂贵的设备：一台高性能电脑、多台显示器、特定的集成开发环境（IDE）和特定的操作系统。

Wrong.错误的。

You need three things: a browser, an internet connection, and a clear thought in your mind.你需要三样东西：浏览器、互联网连接和清晰的思路。

That is it.就是这样。

The tools run in your browser or in a terminal. The AI models run in the cloud. The deployment platforms are free for small projects. There is genuinely no hardware barrier to entry.这些工具可以在浏览器或终端中运行。人工智能模型在云端运行。部署平台对小型项目免费。硬件方面几乎没有任何门槛。

**The real barrier is not technical. It is communication.** AI does not understand your emotions, your aesthetic preferences, or your unstated assumptions. It understands instructions. Clear, specific, unambiguous instructions.**真正的障碍不在于技术，而在于沟通。** 人工智能无法理解你的情绪、审美偏好或你未言明的假设。它只能理解指令，清晰、具体、明确的指令。

Most people who fail at vibe coding fail because they communicate poorly, not because they lack technical ability. They write "build me an app" and get frustrated when the result is generic. The fix is not a better tool. It is a better description.大多数在 Vibe 编程中失败的人，失败的原因并非技术能力不足，而是沟通不畅。他们写“帮我做一个应用”，结果却发现结果千篇一律，于是感到沮丧。解决办法并非开发更好的工具，而是改进描述。

# The 5 Rules of Effective Vibe Coding有效氛围编码的5条规则

These rules separate people who ship real applications from people who get frustrated and quit.这些规则将能够交付真正应用程序的人与那些感到沮丧而放弃的人区分开来。

# Rule 1: Think Before You Prompt规则一：提问前先思考

This is the most important rule and the one most people violate immediately.这是最重要的规则，也是大多数人最先违反的规则。

They open their tool and type: "Build me a to-do list app."他们打开工具并输入：“为我创建一个待办事项清单应用程序。”

They get a generic, basic, useless to-do list.他们得到的是一份通用、基础、无用的待办事项清单。

Then they blame the tool.然后他们就把责任推给工具。

**The problem was the prompt.** "Build me a to-do list app" gives the AI almost zero information about what you actually want.**问题出在提示语上。** “帮我做一个待办事项应用”这样的提示语几乎没有给人工智能提供任何关于你实际需求的信息。

Before you write a single prompt, answer these questions:在编写任何提示之前，请先回答以下问题：

What specifically does this app do? Not "it manages tasks" but "it lets users create tasks with due dates and priority levels, organize them into projects, mark them complete, and see an overview dashboard showing what is overdue."这个应用具体能做什么？它不是“管理任务”，而是“允许用户创建带有截止日期和优先级的任务，将任务组织成项目，标记任务已完成，并查看显示哪些任务逾期的概览仪表板”。

What should it look like? Find screenshots of apps with a design you admire. Save them. You will feed them to the AI as reference.它应该是什么样子？找到一些你欣赏的设计的应用截图，保存下来。你会把它们作为参考提供给人工智能。

What technology should it use? If you do not know, ask the AI: "I want to build \[description\]. What technology stack would you recommend for this and why?" Then use whatever it suggests.它应该使用什么技术？如果你不知道，可以问问人工智能：“我想构建\[描述\]。你会推荐什么技术栈？为什么？”然后就用它推荐的方案。

Who will use it? Just you? A team? Public users? This determines authentication, data storage, and deployment requirements.谁会使用它？只有你一个人？一个团队？还是公众用户？这将决定身份验证、数据存储和部署要求。

**Spending 10 minutes on these questions before prompting saves hours of frustrated iteration.在提出问题之前花 10 分钟思考这些问题，可以节省数小时令人沮丧的反复尝试。**

# Rule 2: One Thing at a Time规则二：一次只做一件事

AI is terrible at complex, multi-part instructions. It is excellent at focused, single-purpose tasks.人工智能不擅长处理复杂的多步骤指令，但它非常擅长处理目标明确、单一目标的任务。

Bad: "Build the settings page with user profile editing, notification preferences, subscription management, and theme customization."错误示例：“构建设置页面，包含用户个人资料编辑、通知偏好设置、订阅管理和主题自定义功能。”

Good:好的：

1. "Build the user profile editing form with fields for name, email, and avatar."“构建用户个人资料编辑表单，包含姓名、电子邮件和头像字段。”
2. "Add notification preference toggles - email notifications, push notifications, weekly digest."“添加通知偏好设置开关——电子邮件通知、推送通知、每周摘要。”
3. "Build the subscription management section showing current plan and upgrade options."“构建订阅管理部分，显示当前套餐和升级选项。”
4. "Add theme customization - light mode, dark mode, and system default."“添加主题自定义功能——浅色模式、深色模式和系统默认模式。”

Four focused prompts. Each one produces polished output because the AI can devote its full attention to one component. Each one is testable independently. If step three breaks, you know exactly where the problem is.四个重点明确的提示。每个提示都能产生高质量的输出，因为人工智能可以全神贯注于一个组成部分。每个提示都可以独立测试。如果第三步出错，你就能准确地知道问题出在哪里。

**Step by step. One job at a time. This is how real developers work and it is how effective vibe coders work too.一步一步来，一次只做一件事。这才是真正的开发者的工作方式，也是高效程序员的工作方式。**

# Rule 3: Use Screenshots, Not Paragraphs规则3：使用屏幕截图，而不是段落

When something looks wrong in your app, do not write a paragraph describing the problem.当你的应用出现问题时，不要写一段文字来描述问题。

Take a screenshot. Circle the issue. Paste it into the AI.截屏。圈出问题所在。将其粘贴到人工智能系统中。

Say: "This spacing is off between the header and the content. The button should be aligned with the input field. The font on the sidebar is too large."可以说：“标题和内容之间的间距不对。按钮应该与输入框对齐。侧边栏的字体太大了。”

Visual feedback is faster, more precise, and produces better fixes than written descriptions. Your eyes are better at detecting visual problems than your words are at describing them.视觉反馈比文字描述更快、更准确，也能更好地解决问题。你的眼睛比你的语言更能准确地发现视觉问题。

# Rule 4: Keep Notes规则 4：做好笔记

At the start of every vibe coding session, tell the AI: "Create a file called [notes.md](http://notes.md/) and save every important decision, architecture choice, and known issue about this project."在每次氛围编码会话开始时，告诉人工智能：“创建一个名为……”的文件 [notes.md](http://notes.md/) 并保存有关此项目的每一个重要决策、架构选择和已知问题。

This single habit changes everything:这一个习惯改变了一切：

You understand how your project works because the decisions are documented. You remember why things were built a certain way. You can explain your project to others. You can onboard another AI tool into the same project because the notes provide full context.因为所有决策都有文档记录，所以您了解项目的运作方式。您记得当初为什么这样设计。您可以向他人解释您的项目。由于文档提供了完整的上下文信息，您可以将其他人工智能工具集成到同一个项目中。

**Without notes, every session starts from scratch.** With notes, every session builds on everything before it.**如果没有笔记，每次学习都得从零开始。** 有了笔记，每次学习都能在前一次学习的基础上进行拓展。

# Rule 5: Save Working Versions规则 5：保存工作版本

Before every major change, commit your working code to Git. If you do not use Git, at minimum copy the working version to a backup folder.每次进行重大更改之前，请将工作代码提交到 Git。如果您不使用 Git，至少应将工作版本复制到备份文件夹。

Vibe coding involves rapid iteration. Sometimes the AI will break something that was working while trying to add a new feature. If you have a saved working version, you roll back in seconds. If you do not, you spend thirty minutes debugging something that used to work.Vibe 编码强调快速迭代。有时，AI 在尝试添加新功能时会破坏原本运行正常的部分。如果你有保存的可用版本，只需几秒钟即可回滚。如果没有，你就得花三十分钟来调试之前运行正常的代码。

```bash
git add .
git commit -m "working version before adding auth"
```

Make this automatic. Every time something works, save it. Every time you are about to make a big change, save first.将此操作设为自动化。每次成功后，都保存下来。每次准备进行重大更改时，都先保存。

# Project Progression: What to Build Next项目进展：下一步该建什么？

Your first project builds confidence. Each subsequent project builds skills.你的第一个项目能建立自信。后续的每个项目都能提升技能。

**Project 2: A tool for someone else.** Build something a friend, family member, or colleague would actually use. This teaches you to think about other users, not just yourself.**项目二：为他人打造工具。** 开发一款朋友、家人或同事真正会使用的工具。这能教会你为其他用户着想，而不仅仅是自己。

**Project 3: A project with a database.** Build something that saves and retrieves data - a bookmark manager, a journal, a recipe collection. This teaches you about data persistence.**项目三：一个基于数据库的项目。** 构建一个能够保存和检索数据的程序——例如书签管理器、日记本或食谱集。这将帮助你学习数据持久化。

# Common Mistakes and How to Avoid Them常见错误及避免方法

**Mistake: "Build me an app."** Too vague. Always describe the specific features, the specific look, and the specific audience before the AI starts building.**错误：“帮我开发一个应用。”** 指令太笼统。在人工智能开始开发之前，务必描述具体的功能、外观和目标受众。

**Mistake: changing everything at once.** Make one change at a time. Test after each change. If you change five things and something breaks, you have no idea which change caused it.**错误：一次性改动所有东西。** 应该一次只改动一个地方，每次改动后都要进行测试。如果你改动了五处，结果出了问题，你就不知道是哪处改动导致的。

**Mistake: ignoring errors.** When you get an error, do not guess. Copy the complete error message and paste it to the AI: "I got this error. What went wrong and how do I fix it?" The AI diagnoses errors better than most junior developers.**错误：忽略错误。** 遇到错误时，不要猜测。复制完整的错误信息并粘贴给 AI：“我遇到了这个错误。哪里出了问题？我该如何解决？” AI 诊断错误的能力比大多数初级开发人员都要强。

**Mistake: never reading the code.** You do not need to write code. But you should develop a basic reading ability. Ask the AI to explain key parts of the code in plain English. Over time, you will develop intuition for how software is structured.**错误：从不阅读代码。** 你不需要编写代码，但你应该培养基本的阅读能力。让 AI 用通俗易懂的语言解释代码的关键部分。随着时间的推移，你会逐渐培养出对软件结构直观的理解。

**Mistake: building without deploying.** A project that only runs on your laptop is a project nobody else can see, use, or give feedback on. Deploy everything. Even if it is ugly. The feedback from real usage is what accelerates your learning.**错误：只构建而不部署。** 一个只能在你电脑上运行的项目，其他人既看不到、用不了，也无法提供反馈。务必部署所有内容，即使它看起来很糟糕。来自真实用户的反馈才能加速你的学习。
