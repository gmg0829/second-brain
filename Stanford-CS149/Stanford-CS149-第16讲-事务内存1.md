# Stanford CS149 第16讲：事务内存（一）

## 课程概述

本讲探讨如何简化共享内存编程中的同步问题，引入**事务内存（Transactional Memory）**概念。

## 核心内容

### 1. 事务内存的动机

传统同步编程困难重重：使用锁实现并发容易导致**死锁（Deadlock）**，且正确实现无锁数据结构需要极高的专业知识。事务内存旨在降低并发编程的复杂度。

### 2. 底层硬件原语

实现同步的核心硬件机制是**原子的 load 和 store**，包括：
- Fetch and Add
- Test and Set
- Compare and Swap（CAS）

现代系统将上述操作拆分为 **load-linked** 和 **store-conditional** 两个指令，由缓存一致性协议保证原子性。

### 3. 事务内存的设计空间

| 维度 | 说明 |
|------|------|
| **实现方式** | STM（软件事务内存）vs HTM（硬件事务内存） |
| **冲突检测** | 乐观检测（检测到冲突再回滚）vs 悲观检测 |
| **并发控制** | 读者-写者分离 vs 统一管理 |

### 4. 冲突检测机制

多个事务同时访问同一数据时触发冲突：
- **写-写冲突**：两事务写入同一地址
- **读-写冲突**：一事务读取、一事务写入同一地址

冲突检测发生在事务提交时，确保原子性。

## 关键结论

事务内存通过将一系列内存操作打包为**原子事务**，让程序员无需手动管理锁即可实现并发安全，显著提升生产效率并降低错误风险。
