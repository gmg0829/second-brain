# Stanford CS149 并行计算第五讲：性能优化 I —— 工作分配与调度

## 课程概述

本讲探讨并行程序性能优化的核心问题：**如何在最小化开销的同时实现良好的工作分配**，并深入讲解 Cilk 框架中的工作窃取（Work Stealing）调度策略。

## 核心概念

### 1. 工作分配（Work Distribution）
- 将计算任务划分为可并行执行的最小工作单元
- 目标：实现**负载均衡（Load Balancing）**，避免线程空闲或过载
- 静态分配 vs 动态分配：静态分配简单但难以应对不均匀负载；动态分配灵活但引入调度开销

### 2. 性能剖析（Profiling）
- 使用计时器定位性能瓶颈
- **关键洞察**：若 95% 时间用于有效计算（如质数检测），则优化空间有限；若大量时间耗在锁竞争，说明并行化策略需要重新设计

### 3. 并行松弛（Parallel Slack）
- 定义：可用处理器数量少于并行工作片段数量时的"空闲空间"
- 意义：提供调度灵活性，可吸收不均匀负载带来的波动

### 4. 工作窃取调度（Work Stealing）
- **空闲线程主动从其他忙碌线程的队列中"窃取"任务**
- 核心思想：让工作量不足的线程去帮助其他线程，而非被动等待
- **Cilk 实现**：每个线程维护自己的任务队列；空闲时从其他线程队列尾部随机窃取任务

### 5. 调度开销最小化
- 将工作划分为**最小粒度**可提高负载均衡概率
- 但过细粒度会增加调度和同步开销
- 需在均衡性与开销之间取得平衡

## 关键要点

| 概念 | 说明 |
|------|------|
| 负载均衡 | 确保所有线程承担大致相等的工作量 |
| 同步屏障 | 多线程程序中用于协调进度的阻塞点 |
| 锁竞争 | 过度同步导致的性能瓶颈 |
| 贪心调度 | 有工作就立即执行的简单策略 |

## 课程总结

性能优化的第一步是**测量**而非猜测。通过剖析工具识别瓶颈后，再针对性地改进工作分配策略或调度机制。工作窃取是实现动态负载均衡的有效方法，尤其适合具有并行松弛的应用场景。
