## 一、硬件多线程（Hardware Multi-Threading）

### 核心思想
> "如果你在等待某事发生，就去做别的事情。" 这是硬件多线程的精髓——当一个线程因内存请求等原因停滞时，硬件自动切换到另一个可运行的线程。

### 工作机制
- 一个核心可维护**多个线程的执行上下文**（如 4 线程、8 线程）
- 每个时钟周期，硬件从可用线程中选择一个执行其下一条指令
- stall 时自动切换（switch on stall），核心始终保持工作状态

### 性能指标
| 指标 | 说明 |
|------|------|
| **利用率** | 可达 100%，但单个线程完成时间会变慢（共享处理器） |
| **吞吐量** | 单位时间内完成的工作量↑ |
| **延迟** | 单个线程的完成时间会因共享而增加 |

### 线程数量计算
```
公式：覆盖stall所需的线程数 ≈ 1 + (stall延迟 / 每线程有效工作时间)
```
例如：每线程做3个操作后stall 12周期 → 需要 **5 线程**（1个stall的 + 4个覆盖的）才能100%利用

### 关键洞察
- 硬件多线程**不提升峰值吞吐量**，而是**提升资源利用效率**
- 程序"数学计算/内存延迟"比值决定所需线程数
- 大数据缓存可减少内存miss，从而减少所需线程数

## 二、Modern Intel CPU 架构实例（Myth Machine）

### 架构组成
- **2路多线程**（Intel 超线程）
- **超标量（Superscalar）**：每周期可执行多条指令
- **SIMD**：至少 3 个 8 wide 向量ALU + 标量ALU
- 每周期峰值：3 × 8 = 24 个浮点操作（使用向量化时）

### 多线程的价值
单线程往往无法填满所有执行资源（ILP不足），多线程让硬件更容易找到足够的独立指令来饱和执行单元。

### 组成堆叠
```
多核 + 多线程 + 超标量 + SIMD = 并行度的完整图景
```

## 三、GPU 架构对比

### Nvidia GPU 特点
- **32-wide SIMD** 每核
- **64 线程上下文** 每核
- 整体芯片需要**数十万并行任务**才能跑满
- GPU 不生成向量指令，只生成标量指令；硬件自动将相同PC的32个线程映射到向量ALU

### 为什么小DNN在GPU上表现差？
> 并行度不够。GPU 需要海量独立任务，小任务无法充分利用其庞大执行资源。

## 四、内存带宽 vs 内存延迟（Latency vs Bandwidth）

### 类比：高速公路
| 场景 | 延迟 | 带宽 |
|------|------|------|
| 一辆车独享高速 | 30分钟（SF→Stanford） | 2辆/小时 |
| 开更快（降低延迟） | 15分钟 | 4辆/小时 |
| 加宽车道（增加带宽） | 不变 | 成倍增加 |
| 车辆紧密跟车（流水线） | 不变 | 大幅增加 |

### 计算机中的类比
- **带宽**：单位时间内完成的数据传输量（如 8 bytes/clock）
- **延迟**：一次数据传输所需时间（如 8 cycles）
- **流水线**：通过在传输过程中重叠多个请求来提升带宽，但单请求延迟不变

### 洗衣房类比（Laundry Pipeline）
```
wash (45min) → dry (60min) → fold (15min) = 120min latency
```
当有多负载时：第一个负载完成wash后立即开始第二个负载的wash → **吞吐提升**，但单个负载的完成延迟不变。

## 五、ISPC 编程抽象

### 为什么介绍 ISPC？
不是为了教语言本身，而是为了**强化 SIMD 和并行概念**。

### ISPC 核心特性
1. **SPMD（Single Program Multiple Data）**：一份程序代码，多个数据实例并行执行
2. **Gang**：ISPC 生成的代码组（gang）包含多个并行的"program instances"
3. **向量化**：编译器将操作映射到 SIMD 指令
4. **交织（Interleaving）**：多个gang轮流执行以隐藏内存延迟

### 性能要求
要在现代并行机上跑满性能，需要：
- **充足的并行任务数**（如 64 threads × 8-wide SIMD = 512 并行度）
- **良好的数据局部性**（减少内存带宽压力）
- **流水线化**（重叠计算与内存访问）

## 六、性能优化策略总结

| 策略 | 作用 |
|------|------|
| **多核** | 增加独立执行单元 |
| **SIMD** | 单指令多数据，压榨数据级并行 |
| **硬件多线程** | 隐藏内存延迟，100%利用执行单元 |
| **超标量** | 挖掘指令级并行（ILP） |
| **缓存优化** | 减少内存访问，降低带宽需求 |
| **流水线** | 重叠操作，提升带宽 |

---

## 关键takeaway

1. **并行度决定性能上限**：需要有足够的独立任务（数千量级）才能充分利用现代并行芯片
2. **延迟与带宽解耦**：减少延迟≠提升带宽，流水线可提升带宽但不降低延迟
3. **评估真实性能**：不能只看峰值 FLOPS，需考虑实际并行度和内存行为
4. **编程模型组合**：多核+SIMD+多线程+超标量组合使用是现代处理器的标配
