# Stanford CS149 并行计算 — 第二讲：A Modern Multi-Core Processor

**时间**：76 分钟 | **主题**：Forms of Parallelism — Multi-Core、SIMD、Multi-Threading

---

## 1. CPU 基本组成

现代处理器可抽象为四个核心组件：

- **Control（控制单元）**：包含 Fetch（取值）和 Decode（译码），负责"下一步执行哪条指令"、分支跳转决策。
- **Execution Unit（执行单元）**：实际完成运算的硬件（ALU 等）。
- **Register State（寄存器状态）**：记录当前执行上下文。
- **Memory（内存）**：程序状态所在，通过 Cache 层级（L1/L2/L3 → DRAM）弥补访问延迟。

**Cache 核心概念**：DRAM 距离远（~250 周期延迟），Cache 本地化数据减少等待。数据以 **cache line**（如 64 字节）为粒度在 DRAM 与 Cache 间传输，具备**时间局部性**（重复访问）和**空间局部性**（连续访问）的程序受益最大。

---

## 2. 多核处理器设计思想

**核心思路**：将整个执行上下文（Fetch/Decode + 执行单元 + 寄存器）完整复制，多个核心各自运行独立的指令流，实现**线程级并行（TLP）**。

- 单核运行一个线程 → 慢 25%，但两个核心同时运行两个线程 → **理论上 2 倍加速**
- 实际收益来自：去掉超深 cache、超复杂的乱序执行逻辑，节省的晶体管用于放置更多简单核心
- 典型案例：多核 CPU（Intel 10核）、GPU（NVIDIA RTX 4090 约 144 个 SM）、Apple Bionic 异构 6 核（2 大核 + 4 小核）

---

## 3. Superscalar vs Multi-Core

| 维度 | Superscalar | Multi-Core |
|------|------------|------------|
| **并行来源** | 硬件在单指令流内找 ILP（指令级并行） | 复制完整核心，支持多指令流并行 |
| **程序改动** | 无需改变程序 | 需要程序提供多线程/多进程 |
| **资源消耗** | 复杂依赖分析 + 深 cache + 预取器 | 复制核心逻辑，cache 更小 |
| **适用场景** | 指令内部有 ILP | 迭代间无依赖（如数组循环） |

> "两种方案晶体管预算相当：用两个晶体管，要么造一个超标量处理器，要么造两个简单核心。"

---

## 4. SIMD（Single Instruction Multiple Data）

**核心思路**：一条指令同时操作多个数据元素（向量化）。

- 将标量寄存器扩展为 **向量寄存器**（如 256-bit = 8×32-bit float）
- 将 `for i = 0 to n` 改造为 `for i = 0 to n by 8`，循环体内部对 8 元素同时执行
- 硬件上：多个 ALU 被同一控制信号驱动，同步执行相同操作

**带宽叠加**：
- 16 核 × 每核 8-wide SIMD = **128 个并行执行单元**
- 理论峰值性能：单核单 ALU 的 128 倍

**效率问题（Divergence）**：若循环体内有分支（if/else），不同元素走向不同路径，SIMD 必须执行所有分支并用 mask 屏蔽无用结果，最坏情况利用率降至 **1/8**（Intel SIMD 宽度=8，GPU 可达 1/32）。

---

## 5. Multi-Threading（多线程并行）

**核心思路**：在单一核心上快速切换多个线程，掩盖内存访问等长延迟。

- 当一个线程发生 Cache Miss 长时间等待时，硬件立即切换到另一线程继续执行
- 理想情况：**ALU 利用率 100%**，单线程延迟略有增加，但整体吞吐最大化
- 与 Multi-core 的区别：Multi-core 是**空间上**复制核心；Multi-threading 是**时间上**复用执行单元

**形象比喻**：洗衣+做饭——洗衣服时烧水（不等待），水开时衣服已洗完，并行完成两件事。

---

## 6. 实际例子

### 向量化（SIMD）示例
```c
// 标量版
for (i = 0; i < n; i++)
    Y[i] = sign_approx(X[i]);

// SIMD 向量化版（ intrinsics / 编译器向量化）
for (i = 0; i < n; i += 8) {   // 每次处理 8 个元素
    // 向量寄存器操作，一次完成 8 次相同计算
}
```

### 多线程（Multi-Core）示例
```c
// fork-join 并行
#pragma omp parallel for
for (i = 0; i < n; i++)
    Y[i] = sign_approx(X[i]);
// 编译器/运行时在 16 核机器上自动生成 16 条指令流
```

### 矩阵乘法的 SIMD + Multi-Core 组合
- 外层循环分片（Multi-Core，多个线程各自处理矩阵的一部分）
- 内层循环向量化（SIMD，单指令多数据加速运算）
- 最终收益 = 核数 × SIMD 宽度

---

## 7. 本讲总结：并行计算三大形式

| 形式 | 并行粒度 | 硬件实现 | 程序改动 |
|------|---------|---------|---------|
| **Multi-Core** | 线程级（TLP） | 复制整个核心 | 显式多线程 / parallel for |
| **SIMD** | 数据级（DLP） | 向量寄存器 + 多个 ALU | 向量化 intrinsics / 编译器自动向量化 |
| **Multi-Threading** | 线程级（TLP） | 时间片切换掩盖延迟 | 线程级并行（OS 调度） |

三者**正交**可叠加：16 核 + 每核 8-wide SIMD + 每核 4 线程 = **128 并行操作/时钟周期**。

> 课程预告：后续将讨论这些并行形式如何与 Memory 层级协同，以及如何真正"将数据送进计算单元"——数据搬移的代价往往比计算本身更昂贵。
