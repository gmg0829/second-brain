# Stanford CS149 并行计算 — 第八讲：数据并行思维

## 概述

本讲从算法角度深入探讨**数据并行**思维方式——不同于此前基于线程的思考模式，转而以"大型数组/数据集"为原语来表达计算。

## 核心概念

### 数据并行操作原语

| 原语 | 作用 |
|------|------|
| **Map** | 对数组每个元素独立应用函数 |
| **Reduce** | 将数组元素归约为单个值（如求和、最大值） |
| **Scan / Prefix Sum** | 计算所有前缀结果，输出与输入等长的数组 |
| **groupByKey** | 按键分组，聚合相同键的所有值 |

### 为什么需要数据并行思维？

- GPU 等硬件支持大规模并行执行上下文（如 163,000+ 个上下文）
- 数据集规模应匹配或超过硬件并行能力
- 将计算表达为数据操作，比显式线程管理更易高效实现

## 典型模式

```
map      → 独立变换每个元素
reduce   → 聚合所有元素为一个结果
scan     → 保留中间状态（可用于动态规划）
groupByKey → 键值分组后按组聚合
```

## 设计启示

数据并行思维将**计算**从"线程执行什么"转变为"数据如何被变换"，这使得运行时系统能更灵活地调度任务、平衡负载，是现代并行系统（Spark、GPU 编程等）的核心抽象。
