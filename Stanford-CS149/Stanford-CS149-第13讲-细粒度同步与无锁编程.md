## 核心概念

### 同步问题基础术语

在深入细粒度同步之前，需明确三个关键概念：

- **死锁（Deadlock）**：所有线程相互等待对方释放资源，形成循环依赖。例如十字路口中四辆车相互阻塞，每辆车都需要前方道路空出才能前进。
- **活锁（Livelock）**：线程虽未阻塞，但因不断响应彼此动作而无法取得实际进展。
- **饥饿（Starvation）**：某些线程长期无法获得所需资源，无法执行。

## 细粒度锁（Fine-Grained Locking）

### 核心思想
将粗粒度的大锁拆分为多个小锁，按数据结构的物理分区分配锁，实现**锁的分区隔离**。

### 典型模式

| 模式 | 描述 | 适用场景 |
|------|------|----------|
| **分段锁（Segment Lock）** | 数组/列表分段，每段独立加锁 | Hash表、计数器数组 |
| **读写锁分离（Reader-Writer Lock）** | 读者并发，写者独占 | 读多写少的数据结构 |
| **单读者单写者队列（SRMW Queue）** | 队头队尾各一把锁 | 生产者-消费者场景 |

### 优势
- 减少锁竞争，提高并发度
- 允许多个线程同时操作数据结构的不同部分

### 挑战
- 实现复杂度显著增加
- 需仔细分析数据结构的物理分区

## 无锁编程基础（Lock-Free Programming）

### 为什么需要无锁？
即使细粒度锁也可能导致**同步开销过高**。无锁编程通过硬件支持的**原子操作（Atomic Operations）**实现线程安全。

### 关键硬件原语

| 原语 | 作用 |
|------|------|
| **CAS（Compare-And-Swap）** | 比较并交换，是无锁算法的基石 |
| **LL/SC（Load-Linked/Store-Conditional）** | 另一种原子操作原语 |
| **原子读/写/递增** | 最基础的原子操作 |

### 无锁栈（Lock-Free Stack）

**基本思路**：使用 CAS 保证 push/pop 的原子性。

```
push(node):
  node.next = top
  while !CAS(top, node.next, node)  // 重试直到成功
```

**问题**：无锁算法需处理** ABA 问题**。

### ABA 问题

**场景**：线程 A 读取栈顶为 A，准备 CAS 时被其他线程干扰：

1. 线程1 读取 top = A
2. 线程2 Pop A、B，CAS(..., A, C) 成功，top → C
3. 线程2 Push A 回栈顶，top → A
4. 线程1 误认为栈顶仍为 A，执行 CAS(..., A, B) — **错误！A 已被替换过**

**解决方案**：
- ** Hazard Pointers**：每个线程记录"正在访问"的指针，其他线程在回收节点前需检查
- **引用计数（Reference Counting）**：带原子计数的节点
- **标记指针（Tagged Pointers）**：用版本号区分同一地址的不同使用

---

## Hazard Pointers 详解

### 工作机制

1. **登记阶段**：线程访问节点前，在线程本地存储中登记该指针为 "hazard"
2. **检查阶段**：任何线程释放节点前，需确认无其他线程将其登记为 hazard
3. **回收阶段**：确认安全后，节点方可被回收复用

### 优点
- 无需垃圾回收器也能安全回收内存
- 开销可控，被广泛用于内核和高效库

## 总结

| 主题 | 关键要点 |
|------|----------|
| **细粒度锁** | 分段隔离、读写分离，适合读多写少场景 |
| **无锁栈** | CAS + 重试机制，需处理 ABA 问题 |
| **ABA 问题** | 用版本号或 Hazard Pointers 解决 |
| **Hazard Pointers** | 线程本地登记 + 全局安全检查，安全回收内存 |
