## 📜 三、程序本质：指令序列

### 什么是计算机程序？
- **定义**：程序是一系列**指令（instructions）**的列表
- **指令做什么**：
  - 执行算术运算（加法、乘法等）
  - 修改状态（寄存器值、内存值）

### 处理器的简化模型
```
[控制单元] → 决定下一步执行哪条指令
[执行单元] → 执行算术/逻辑运算（黄色）
[执行上下文] → 寄存器和内存的状态（蓝色）
```

### 指令执行示例
```assembly
add r0, r1, r2   ; r0 = r1 + r2
```
执行过程：
1. 从寄存器读取 r1, r2 的值
2. 执行加法运算
3. 将结果写回 r0
4. 更新程序计数器

## ⚡ 四、指令级并行（ILP）与瓶颈

### 超标量执行（Superscalar）
- 现代处理器可以在**一个时钟周期**内执行多条指令
- 通过**乱序执行（Out-of-Order Execution）**发现指令间的并行性

### 关键发现：程序并行性有限
斯坦福早期研究表明：
- 即使编译器做得很聪明，程序固有并行性通常只能支撑 **3-4 条指令/周期** 的并行执行
- 超过这个范围，增加更多执行单元也无法提升性能

### 依赖链示例
```assembly
inst1: r0 = r1 + r2    ; 依赖 r1, r2
inst2: r3 = r0 + r4    ; 依赖 inst1 的结果
inst3: r5 = r6 + r7    ; 独立，可并行
inst4: r8 = r3 + r9    ; 依赖 inst2
```
并行机会：`inst1` 和 `inst3` 可同时执行

## 📈 五、硬件演进与免费午餐的终结

### 摩尔定律与晶体管
- 晶体管越来越小 → 可以增加更多晶体管
- 更多晶体管 → 可以有更多执行单元
- 更多晶体管 → 也可以提高时钟频率

### 转折点：时钟频率停止增长
**原因：功耗问题**
```
功耗 ∝ 频率²
```
提高频率会指数级增加功耗和发热，这就是为什么：
- 2000年代CPU频率停在 3-4 GHz
- 不能再靠"等一年，处理器变快"来加速程序

### 现代GPU的功耗类比
- RTX 4090 GPU 在机器学习负载下 ≈ 微波炉的能耗
- 无法无限制提高频率，必须用**并行**换性能

## 🎮 六、多核与专用处理器时代

### 多核处理器
- AMD 最新芯片：64 核
- 典型笔记本：4-8 核
- 关键问题：**串行程序在多核上几乎无法加速**

### 专用处理器趋势
现代芯片不仅有CPU，还有：
- **NPU**：神经网络处理（iPhone 有 6核 CPU + 4核 "小核" + 专用NPU）
- **TPU**：Google 的张量处理单元
- **DSP**：数字信号处理器

### 性能差距的实际案例
```
编译良好的 C++ 程序（利用4核）：
性能提升可达 30-40倍

Python 程序：
几乎无法从多核获益
```

## 🧠 七、程序员的视角：效率的重要性

### 开场故事：10核处理器，2倍加速
**场景**：你在实习/工作中被要求优化一个程序
- 目标机器：10核处理器
- 结果：只实现了 2倍加速

**问题**：该被开除还是该加薪？

**讲师观点**：
- 如果**性能收益足以抵消并行化成本**，2倍加速也可能令人满意
- 例如：搜索响应时间减半 → 用户留存显著提升 → 商业价值巨大
- 反之，如果只用到了20%的算力利用率，可能需要反思

### 效率优先原则
> **"并不是所有问题都值得并行化"**
> **有时候，一个聪明高效的串行算法，胜过一个笨拙的并行方案**

## 💾 八、内存层次与缓存基础

### 为什么内存这么慢？
- DRAM 访问延迟：数百个CPU周期
- 如果每次运算都去内存读数据，CPU会大量时间在**等待**

### 缓存（Cache）的作用
| 存储层次 | 容量 | 延迟 | 类比 |
|---------|------|------|------|
| L1 Cache | ~32KB | 1-2 周期 | 桌面文件 |
| L2 Cache | ~256KB | 5-10 周期 | 书架 |
| L3 Cache | ~MB级 | 10-20 周期 | 抽屉 |
| DRAM | GB级 | 100+ 周期 | 车库 |

### 缓存行（Cache Line）
- 数据从内存传输到缓存的**最小单位**
- 通常是 64 字节（一行）
- **空间局部性**：如果访问了地址 A，往往也会访问 A+1, A+2...

### 实际例子
```c
int sum = 0;
for (int i = 0; i < N; i++) {
    sum += arr[i];  // 顺序访问，缓存友好
}
```

## 🔑 十、关键术语表

| 英文 | 中文 | 解释 |
|------|------|------|
| Instruction-Level Parallelism (ILP) | 指令级并行 | 单线程内指令间的并行执行 |
| Superscalar | 超标量 | 一个时钟周期执行多条指令 |
| Out-of-Order Execution | 乱序执行 | 不按程序顺序执行，利用指令间独立性 |
| Cache Line | 缓存行 | 内存传输到缓存的最小单位 |
| Spatial Locality | 空间局部性 | 访问某地址后倾向于访问附近地址 |
| Temporal Locality | 时间局部性 | 访问某数据后可能再次访问 |
| Amdahl's Law | 阿姆达尔定律 | 并行化收益受限于不可并行部分 |
