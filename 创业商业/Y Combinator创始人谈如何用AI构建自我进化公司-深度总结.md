## 核心观点概述

Tom Blomfield 认为，AI 不仅仅是一个让员工提高20-30%效率的 Copilot 工具，而是能够重新定义公司本身的存在形式。他提出了一种全新的公司架构思维：**将公司视为一系列递归自我改进的 AI 循环（Recursive Self-Improving AI Loops）**。当这种架构真正运转起来时，公司可以在创始人睡眠时依然持续自我优化。

### 00:00 — Companies Are Roman Legions（公司如罗马军团）

Tom 以罗马军团开篇。罗马军团的设计是为了将权力从罗马中心投射到两个大洲之外，通过**嵌套层级（Nested Hierarchies）**、一致的**控制跨度（Span of Control）**运作——由指定的个人传递命令、收集信息，形成自上而下、自下而上的信息流动。

**关键洞察**：Jack Dorsey 的推文指出，当前大多数公司的组织方式依然是罗马军团模式——**人类是信息上下流动的导体**。但 AI 打破了这一假设：层级组织不再是最优的经济单元组织形式。

> "Jack Dorsey 的核心观点是：层级化组织的公司是我们组织经济单元的方式——但 AI 基本上打破了这个假设。"

### 02:24 — The Recursive Self-Improving Loop（递归自我改进循环）

Tom 详细描述了构建自我改进公司的核心机制——**AI Loop（AI 循环）**：

#### 四层架构

```
┌─────────────────────────────────────────────────────┐
│                  1. Sensor Layer（感知层）              │
│  Customer emails / Support tickets / Code changes    │
│  Subscription cancellations / Product telemetry       │
│  → 从外部世界获取信息的传感器数据                       │
└─────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────┐
│              2. Policy Layer（策略层）                 │
│  决策规则：什么能做、什么需要人类许可、什么必须记录       │
└─────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────┐
│                 3. Tool Layer（工具层）               │
│  确定性 API：查询数据库、查看日历等                    │
│  Quality Gates：评估检查、安全过滤、高风险人工审核      │
└─────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────┐
│              4. Learning Mechanism（学习机制）         │
│  系统与真实世界互动，发现不 work 的地方，循环回到顶部    │
└─────────────────────────────────────────────────────┘
```

**核心原则**：如果每一步都能在**最小人工干预**下运行，系统会越来越好、越来越好——**即使你在睡觉**。

#### YC 的实际案例演进

**阶段一（去年版本）**：一个 Agent，可以回答问题、查询数据库（"我上次和这家公司进行 office hours 是什么时候？"）

**阶段二（更智能）**：能够进行更复杂的查询——比如识别需要石化行业相关人脉的公司，然后通过 RAG 等技术从数据库中找到5个相关的创始人推荐给合伙人

**这仍然是 Copilot 模式**：让人变得20-30%更高效

### 08:05 — Make Everything Legible to AI（让一切对 AI 可读）

这是构建自我改进公司的**第一步**：

#### 核心原则
> **"如果一件事没有被记录，它就没有发生在 AI 的认知中。"**

#### YC 的实践

- 每条 Slack 消息、每个 DM
- Office Hours 的录音（过去3-4个月开始记录）
- **如果发生了但没有被记录，就等于没有发生**

#### Tom 的个人反思
在和创始人交谈时，他意识到自己会忘记很多对话内容（"我要和20个人谈话"），所以他现在认为：

> "你需要让整个组织对 AI 可读。这意味着你必须记录一切。如果没有被记录，它就没有发生在 AI 的认知中。"

#### DiRAGization（压缩/摘要化）

1. **DiRAGization（压缩）**：将信息聚合、综合，提取重要部分

### 11:19 — Software Is Ephemeral, Context Is Valuable（软件是短暂的，上下文是珍贵的）

Tom 提出了一个关于**什么应该被持久保存**的重要观点：

#### Gary Vaynerchuk 的做法
- Gary 将所有 Email 转换为 Markdown 格式
- **永远不丢弃任何东西**
- 但把软件视为**可消耗的（Disposable）**

#### Tom 的诠释
> "我会非常珍惜地存储所有数据。但同时我会把软件视为完全可消耗的。"

**核心洞察**：

| 珍贵（需要保存） | 短暂（可丢弃） |
|-----------------|---------------|
| 所有数据（Email、DM、会议录音） | 内部 Dashboard |
| 业务上下文（Context） | 运营工作流代码 |
| Skills / Knowhow | 单次使用的软件 |
| 业务逻辑的认知 | 特定功能的实现 |

#### 原因
- **Models 每个月都在变得更好**（两个月后模型升级，现有软件就可以丢弃重写）
- 每次模型更新，给它原始指令集，重新生成软件
- 真正珍贵的是**人们头脑中对"这个功能如何运作"的理解**

> "业务上下文和 skills 是珍贵的东西。顶层的软件是短暂的。你能生成它，就能重新生成它。"

## 总结：构建AI原生公司的行动指南

1. **转变思维**：从"AI 作为 Copilot 工具"转向"公司作为递归自我改进的 AI 循环"
2. **提取领域知识**：将存在于人脑、Slack、Email、Notion 中的隐性知识显性化
3. **记录一切**：确保所有信息可被 AI 访问（"没有记录=没有发生"）
4. **建立四层循环**：Sensor → Policy → Tool → Learning，实现最小人工干预的自动化
5. **监控并自动优化**：用 AI 监控 AI，自动发现失败案例并编写代码修复
6. **Burn Tokens, Not Headcount**：用 token 投入替代人头扩张
7. **消除中层管理**：每个人都是 IC，需要明确的第一责任人
8. **让软件成为消耗品**：珍贵的是数据和上下文，不是具体某段代码
9. **人类在边缘**：人类负责与 AI 暂时无法触及的真实世界接口——高风险决策、道德判断、创新场景
10. **立即行动**：对于初创公司，现在是重新设计公司架构的最佳时机
