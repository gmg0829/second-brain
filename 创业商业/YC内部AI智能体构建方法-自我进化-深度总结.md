## 三、Agent架构详解

**时间戳：00:01:15 - 00:02:05**

### 3.1 核心架构：Python包装的Claude Code CLI

架构的第一层是**用Python包装的Claude Code CLI**：

```
Slack/Email/其他渠道 → 任务队列(Task Queue) → Python包装层 → Claude Code CLI
```

**工作流程：**
1. 来自Slack、Email等渠道的新消息进入**任务队列（Task Queue）**
2. Agent从队列中获取任务
3. **迭代式处理**这些任务

### 3.2 为什么选择Claude Code？

Claude Code作为核心引擎表现优异，原因在于它**已经具备的能力**：

- ✅ 检查文件（inspect files）
- ✅ 运行命令（run commands）
- ✅ 使用CLI工具（use CLIs）

这使得它天然适合作为AI Agent的"控制中枢"（thin harness）。

## 四、让Agent理解业务逻辑

**时间戳：00:02:07 - 00:02:23**

### 4.1 给Agent提供业务上下文

 Ayush Garg发现的有效方法是：**给Agent提供只读的代码库和数据库副本**

**实现方式：**

- 设置一个**cron job**
- 每次发布（release）时自动更新Agent的知识库
- Agent可以阅读代码库来回答关于业务的问题

### 4.2 Agent能理解的内容

当客户支持查询涉及业务问题时，Agent现在能够：

- 阅读代码库来理解业务逻辑
- 理解订阅逻辑（subscription logic）
- 定位应用内部的各种功能模块

## 五、Agent的自我进化机制（核心创新）

**时间戳：00:02:41 - 00:03:28**

### 5.1 两大关键组件

这才是真正让Agent能够**自我进化（self-evolving）**的核心：

#### 组件一：工具集（Tools）
所有初创公司使用的工具都被封装为CLI：
- Intercom
- Fathom
- Stripe
- 其他第三方服务

#### 组件二：编码子代理（Coding Sub-agent）
- 也是一个CLI
- **能够编辑Agent自身的代码**

### 5.2 自我进化的工作原理

**时间戳：00:03:02 - 00:03:25**

```
当被要求完成一个尚无法完成的任务时 →
Agent调用coding sub-agent →
Coding sub-agent构建新工具 →
新工具变为永久可用 →
在未来的会话中继续存在
```

### 5.3 进化成果

从"骨架"到"完整工具"的演变：

- **已自主构建超过45个CLI工具**
- Agent从最初只能做简单的事情，发展成为功能完整的运营助手
- 典型案例：只需告诉它"监控我们的着陆页确保广告始终可用"，它就**自动创建了cron job来执行监控**

## 六、可编辑的个性与记忆系统

**时间戳：00:03:40 - 00:04:04**

### 6.1 instructions.md文件

Agent通过一个**instructions.md文件**来实现可编辑的个性/记忆：

- 该文件在**每次Agent turn时加载**
- **Agent本身可以编辑这个文件**
- 这是自我进化的关键机制

### 6.2 像员工一样给予反馈

Ayush Garg这样描述：

> 我们可以像给员工反馈一样给Agent反馈，Agent会直接更新instruction.md文件，该文件会在下次运行时被附加进去。

## 七、真实进化案例

**时间戳：00:04:04 - 00:04:31**

### 7.1 联合创始人的Slack反馈

当Agent刚开始做客户支持时，联合创始人Ryan（非技术背景）注意到**一类支持错误**。

**传统做法的对比：**

| 传统做法 | 新做法的实际流程 |
|---------|----------------|
| 打开代码库 | ❌ 不需要 |
| 告诉创始人 | ❌ 不需要 |
| 提交工单 | ❌ 不需要 |
| **在Slack上直接消息Agent** | ✅ 直接告诉Agent哪里做错了 |

### 7.2 进化结果

Agent的响应：
1. 更新了自身的指令集（instruction set）
2. 更新了工具链接（tool link）
3. **这类错误从此彻底消失**

### 7.3 核心教训

> 一个内部Agent需要三种类型的记忆（Three Sorts of Memories）。

## 八、三种记忆系统（核心框架）

**时间戳：00:04:31 - 00:05:02**

这是Ayush Garg总结的**适用于任何创始人的框架**：

### 8.1 事实记忆（Factual Memory）

| 属性 | 内容 |
|------|------|
| **定义** | 代码库和数据库的结构与内容 |
| **内容** | 应用内部是如何运作的 |
| **用途** | 帮助Agent理解业务的技术实现 |

### 8.2 行为记忆（Behavioral Memory）

| 属性 | 内容 |
|------|------|
| **定义** | 教给Agent的东西——指令和反馈 |
| **实现方式** | instructions.md文件 |
| **特点** | 可以不断更新和积累 |

### 8.3 程序记忆（Procedural Memory）

| 属性 | 内容 |
|------|------|
| **定义** | 定期执行的任务流程 |
| **实现方式** | Agent自主创建的工具 |
| **特点** | 将重复性任务自动化并持久化 |

## 九、复制该系统的完整步骤

**时间戳：00:05:02 - 00:05:35**

### 9.1 搭建清单

按照优先级排列的5个步骤：

#### Step 1: 选择主Agent引擎
- 使用Claude Code
- 或任何具备编码能力的CLI

#### Step 2: 给予代码库只读权限
- 让Agent能够阅读和理解代码库

#### Step 3: 提供基础CLI工具
- 连接核心工具（Intercom、Stripe等）

#### Step 4: 集成Coding Sub-agent
- 让Agent能够编写和修改自身代码
- 这是自我进化的关键

#### Step 5: 配置可编辑的指令文件
- 设置instructions.md
- 确保每次运行都会加载

### 9.2 通讯集成

- 通过SSH连接Slack或Email
- 任务会自动进入队列

## 十、关键经验总结

### 10.1 核心洞察

1. **不仅仅是固定任务执行**：自我进化能力才是AI Agent的核心价值
2. **瘦 harness 优先**：选择已经具备文件检查、命令执行、CLI使用能力的工具
3. **让非技术人员也能参与训练**：通过Slack消息直接反馈
4. **三种记忆缺一不可**：事实、行为、程序记忆共同构成完整的AI Agent

### 10.2 与传统方式的对比

| 对比维度 | 传统方式 | AI Agent方式 |
|---------|---------|-------------|
| 工具扩展 | 需手动开发 | Agent自主构建 |
| 知识传递 | 需文档/培训 | 直接通过反馈学习 |
| 问题修复 | 提交工单→排队→修复 | Slack消息→即时解决 |
| 扩展成本 | 线性增长 | 边际成本趋近于零 |

### 10.3 该系统的本质

> **让AI Agent从一个只能执行固定任务的工具，变成一个能够自我扩展、自我学习、自我进化的数字员工。**

## 十二、实用建议

### 12.1 起步建议

1. **从简单开始**：先用Claude Code处理邮件分类
2. **给予上下文**：提供代码库只读访问
3. **建立反馈循环**：通过Slack让团队直接给Agent反馈
4. **允许自我修改**：集成coding sub-agent，让Agent能构建自己的工具

### 12.2 避免的误区

| 误区 | 正确做法 |
|------|---------|
| 试图一步到位构建完美Agent | 从简单开始，逐步扩展 |
| 只给固定任务 | 设计自我进化的能力 |
| 忽视反馈机制 | 建立便捷的反馈渠道（非技术创始人也能参与） |
| 忽略三种记忆的平衡 | 事实、行为、程序记忆缺一不可 |
