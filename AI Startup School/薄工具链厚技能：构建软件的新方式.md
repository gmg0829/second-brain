# 薄工具链厚技能：构建软件的新方式

**来源**：Y Combinator，Gary Tan 与 Paul Livengood 对谈

---

## 核心洞察

- **"薄工具链、厚技能"范式**：Gary Tan 重新编写的 Posterous（第三次重建）仅花费约200美元（Claude Code Max 账户）和5天时间，而2008年首个版本耗资400万美元、6-7人和一年半。核心转变在于：**不再重复造轮子构建 LLM 调用框架（工具链），而是专注于写好 Markdown 指令（技能）**——即把描述性、引导性的内容写入 Markdown，让 LLM 处理模糊的、通用的情况，而代码只处理确定性的、边界清晰的部分。

- **Token Maxxing（代币最大化）的力量**：Gary 的方法论核心是用更多 token 消耗换取更完整、更优质的结果。如果一个研究任务人类需要一个月，机器可以用更高的 token 消耗"碾压"完成——这不只是节省时间，而是用机器的"意识时间"换取人类的专注力。Gary 将这比作用机器的"数百万年机器意识"来购买自己的时间，成为"时间亿万富翁"。

- **AI Agent 像法拉利——你得是 mechanic**：使用 OpenClaw/Cursor 等工具就像开法拉利——令人振奋、能完成超乎想象的任务，但也会在最需要时抛锚，你需要自己"掀开引擎盖"修理。这要求工程师具备真正的领域知识和调试能力，而不是只会复制粘贴代码。

- **80-90% 测试覆盖率是底线**：Gary 踩过的坑——vibe coding 产生的"slop"在80%情况下看似OK，但真实用户一接触就崩溃。核心认知：**没有测试的 AI 生成代码比人类代码更危险**，因为你完全不知道会发生什么。用 token 换测试覆盖率是值得的。

- **个人 AI 是下一个 Personal Computer 革命**：Gary 预言每个人都将有自己的个人 AI——拥有自己的数据、自己的集成、自己的提示词，控制自己的工具和数据。或者选择被企业算法控制，就像今天的社交媒体信息流一样。**核心问题：是你的工具控制你，还是你控制你的工具？**

---

## 可执行要点

1. **用 Markdown 承载工作流知识，用代码处理确定性逻辑**：Gary 的经验是——如果你在写代码来处理"用户意图理解"这类事情，注定失败。应该把描述性的引导写入 Markdown，把确定性动作（发短信、API 调用）留给代码。

2. **在 AI 编码中坚持 80-90% 测试覆盖率**：不要因为 AI 生成代码快就跳过测试。相反，要用 AI 来帮你写测试——用更多 token 消耗换得完整的测试保障，这是性价比最高的投入。

3. **用"token maxxing"心态做重要的事**：对于真正重要的产品/功能，值得每天花费数百美元在 token 消耗上。Gary 将其比作在旧金山付高房租——**省小钱会让你错失真正的价值**，对 founders 来说 token maxxing 是你应该尽可能push的投入。

4. **始终保持人类在循环中**：Gary 明确表示他永远不想完全脱离循环——他只想让机器做他不想做的事。人类需要提供：动机、理解、上下文、质量判断。真正的 AGI 不会让人类出局，反而会让人类插上翅膀。

5. **用 Plan Mode + CEO Skill 驱动 AI 工作流**：Gary 的 GStack 流程：Plan Mode 规划 → CEO Review 评估野心程度 → Developer Review 检查代码质量 → 人工批准 → AI 执行。对于重要的决策，"想象 Brian Chesky 坐在你身边，问什么是六星级体验"是一个强大的思维工具。

6. **不要只看 OpenClaw 的失败，要看到 AI 编程的必然趋势**：Gary 承认 OpenClaw/Cursor 还有诸多 failure cases，但这是 Homebrew Computer Club 时刻——是早期采用者的探索阶段，工具虽然粗糙但方向正确。明年今天每个人都会有自己的个人 AI。
